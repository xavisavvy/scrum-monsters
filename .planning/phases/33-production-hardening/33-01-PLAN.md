**server/index.ts — Fix graceful shutdown handler (lines 188-237):**

In the `gracefulShutdown` function, the existing code emits `server_shutdown` and waits 2 seconds, but never calls `io.close()`. The `server.close()` on line 226 stops new HTTP connections but does NOT close existing WebSocket connections (confirmed by Socket.IO maintainers in discussion #5030).

Modify the shutdown sequence so that `io.close()` is called AFTER the 2-second notification wait and BEFORE `server.close()`. The updated order must be:

1. Emit `server_shutdown` to all clients (already exists, lines 201-207)
2. Wait 2 seconds for clients to receive notification (already exists, line 207)
3. **NEW: Call `io.close()` to disconnect all WebSocket connections cleanly**
   ```typescript
   // Close Socket.IO connections (server.close() alone does NOT close WebSockets)
   await new Promise<void>((resolve) => {
     io.close(() => resolve());
   });
   ```
4. Clean up WebSocket intervals (already exists, lines 211-213)
5. Close Redis (already exists, lines 215-216)
6. Close database (already exists, lines 218-223)
7. Close HTTP server via server.close() (already exists, lines 225-228)

Insert the `io.close()` call inside the existing `if (io)` block, after the 2-second wait (line 207) and before the cleanupWebSocket call (line 211). The io.close() callback-based API matches Socket.IO 4.x which is what this project uses.

**docker-compose.prod.yml — Three changes to the app service:**

1. Add `stop_grace_period: 45s` to the app service (after the `image:` line, before `restart:`). This gives the Node.js SIGTERM handler 45 seconds to drain before Docker sends SIGKILL. The default is 10s which is too short for the 30-second force-exit timeout in server/index.ts. The 15-second buffer (45s - 30s) prevents a race between clean exit and SIGKILL.

2. Replace `OAUTH_CALLBACK_BASE_URL: https://scrummonsters.com` (line 19) with `BASE_URL: https://scrummonsters.com`. The old variable is dead — it was for Passport.js (removed in Phase 32). Auth0 in `server/auth/auth0.ts` reads `process.env.BASE_URL`. The `server/config/env.ts` already declares `BASE_URL` as optional.

3. Keep `build: .` and `image: scrummonsters:latest` for now — Task 2 will replace them with the GHCR image reference. Do NOT remove them in this task.

Do NOT change the postgres, nginx-proxy-manager services, volumes, or any other parts of docker-compose.prod.yml in this task.

**docker-compose.prod.yml — Replace local build with GHCR pull and add backup sidecar:**

1. In the app service, replace:
   ```yaml
   build: .
   image: scrummonsters:latest
   ```
   with:
   ```yaml
   image: ghcr.io/xavisavvy/scrum-monsters:${APP_IMAGE_TAG:-latest}
   ```
   Remove the `build:` key entirely. The image is now pulled from GHCR, pre-built by the docker.yml GitHub Actions workflow. The `APP_IMAGE_TAG` env var defaults to `latest` but can be overridden to any sha or semver tag for rollback.

2. Add a new `postgres-backup` service after the postgres service:
   ```yaml
   postgres-backup:
     image: eeshugerman/postgres-backup-s3:17
     environment:
       SCHEDULE: "0 2 * * *"
       BACKUP_KEEP_DAYS: "7"
       S3_REGION: us-east-1
       S3_ACCESS_KEY_ID: ${BACKUP_S3_ACCESS_KEY_ID}
       S3_SECRET_ACCESS_KEY: ${BACKUP_S3_SECRET_ACCESS_KEY}
       S3_BUCKET: ${BACKUP_S3_BUCKET}
       S3_PREFIX: scrummonsters
       POSTGRES_HOST: postgres
       POSTGRES_DATABASE: ${POSTGRES_DB}
       POSTGRES_USER: ${POSTGRES_USER}
       POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
     depends_on:
       postgres:
         condition: service_healthy
     restart: unless-stopped
   ```
   The `:17` tag matches the postgres:17-alpine version. SCHEDULE is cron format for 2am UTC daily. BACKUP_KEEP_DAYS=7 is local retention; the 30-day retention is handled by S3 Lifecycle Policy (configured by human in Plan 02). The POSTGRES_* vars reuse the same .env values as the postgres service.
