Create `client/src/lib/stores/useTutorial.tsx` -- a Zustand store using `persist` middleware from `zustand/middleware` with `createJSONStorage(() => localStorage)`.

**State shape:**
```typescript
interface TutorialState {
  // Persisted (via partialize)
  completedTutorials: Record<string, boolean>;
  completedHints: Record<string, boolean>;
  version: number;

  // Runtime-only (NOT persisted)
  activeTutorial: string | null;
  activeStep: number;
  isSpotlightVisible: boolean;
  isHydrated: boolean;

  // Actions
  startTutorial: (id: string) => void;
  advanceStep: () => void;
  completeTutorial: (id: string) => void;
  dismissHint: (id: string) => void;
  resetTutorial: (id: string) => void;
  resetAllTutorials: () => void;
}
```

**Critical implementation details:**
- Use `partialize` to ONLY persist `completedTutorials`, `completedHints`, and `version`. All runtime state (`activeTutorial`, `activeStep`, `isSpotlightVisible`, `isHydrated`) must NOT be persisted.
- Storage name: `'scrumquest-tutorial'`
- Version: `1`
- Include `migrate` function that handles version 0 -> 1 (return state as-is with version: 1).
- Set `isHydrated` to `true` in the `onRehydrateStorage` callback's success handler (the second argument function): `onRehydrateStorage: () => (_state, error) => { if (!error) { useTutorial.setState({ isHydrated: true }); } }`
- `startTutorial(id)`: Sets activeTutorial to id, activeStep to 0, isSpotlightVisible to true. If `completedTutorials[id]` is true, still allow restart (don't guard against it -- the help menu uses this for replay).
- `advanceStep()`: Increment activeStep by 1.
- `completeTutorial(id)`: Set `completedTutorials[id] = true`, clear `activeTutorial` to null, `activeStep` to 0, `isSpotlightVisible` to false.
- `dismissHint(id)`: Set `completedHints[id] = true`.
- `resetTutorial(id)`: Remove `id` key from `completedTutorials` using destructuring rest.
- `resetAllTutorials()`: Set both `completedTutorials` and `completedHints` to empty objects `{}`.

**Unit tests** in `client/src/lib/stores/useTutorial.test.ts`:
- Use vitest with `@testing-library/react` renderHook pattern (import from 'vitest' and '@testing-library/react').
- Before each test: clear localStorage, reset store to initial state via `useTutorial.setState(...)`.
- Test cases:
  1. Initial state has empty completedTutorials/Hints, null activeTutorial, step 0
  2. startTutorial sets activeTutorial, step 0, spotlight visible
  3. advanceStep increments activeStep
  4. completeTutorial marks as complete and clears active state
  5. dismissHint marks hint as complete
  6. resetTutorial removes specific tutorial from completed
  7. resetAllTutorials clears all completions
  8. partialize only persists completedTutorials, completedHints, version (verify by checking localStorage JSON)

**Create `client/src/lib/hooks/useHintTarget.ts`:**

```typescript
interface HintRect {
  top: number;
  left: number;
  width: number;
  height: number;
  bottom: number;
  right: number;
}
```

Export `useHintTarget()` hook that returns `{ targetRect, locateTarget, trackTarget }`:
- `targetRect`: `HintRect | null` state.
- `locateTarget(targetId: string): HintRect | null` -- Uses `document.querySelector('[data-hint-target="TARGETID"]')` to find element, calls `getBoundingClientRect()`, copies values into a plain `HintRect` object (not the live DOMRect), updates state, returns the rect or null.
- `trackTarget(targetId: string): () => void` -- Starts a `requestAnimationFrame` loop that calls `locateTarget` each frame. Returns a cleanup function that calls `cancelAnimationFrame`. Store the raf ID in a `useRef<number>`. Only use this for moving elements -- static elements should use `locateTarget` once.
- Add a `useEffect` cleanup that cancels any active RAF on unmount.
- Add a resize/scroll listener inside the hook: when `targetRect` is non-null, add `window.addEventListener('resize', ...)` and `window.addEventListener('scroll', ...)` that re-call `locateTarget` with the last-used targetId. Store the last targetId in a ref. Debounce resize to 100ms using setTimeout. Clean up listeners on unmount.

**Add data-hint-target attributes to game elements (minimal, surgical changes):**

1. `BossDisplay.tsx` -- Find the HealthBar component or its wrapper div. Add `data-hint-target="boss-health"` to the wrapper element that contains the health bar.

2. `ScoreSubmission.tsx` -- Find the vote card grid (the div with className containing grid that maps over scoring options). Add `data-hint-target="vote-cards"` to that grid container div.

3. `PlayerHUD.tsx` -- Add `data-hint-target="player-info"` to the div with className "flex items-center gap-4" that wraps the player avatar and name. Also add `data-hint-target="player-hud"` to the outermost div with className "player-hud pb-safe".

4. `AbilityBar.tsx` -- Add `data-hint-target="ability-bar"` to the outermost container div of the AbilityBar component (the first div after the early returns).

These are attribute-only changes -- no logic, no imports, no styling changes. Just adding data-hint-target props to existing elements.
