  <name>Task 1: Create MetricsCollector with process + Prometheus + event loop sampling</name>
  <files>tests/profiling/metrics-collector.ts</files>
  <action>
Create `tests/profiling/metrics-collector.ts` that captures three categories of metrics during a profiling run:

**1. Process metrics (polled at 1000ms intervals):**
- `process.memoryUsage()` — heapUsed, heapTotal, rss, external
- `process.cpuUsage()` — user and system microseconds (calculate delta between samples)
- Store each sample with timestamp

**2. Event loop utilization:**
- Use `perf_hooks.performance.eventLoopUtilization()` to capture ELU at each sample interval
- Track idle%, active%, and utilization ratio
- Flag if utilization exceeds 90% (event loop blocking indicator)

**3. Prometheus metrics (fetched via HTTP):**
- Fetch `http://localhost:5000/metrics` at start and end of profiling
- Parse `scrumquest_websocket_connections` gauge for connection count
- Parse `scrumquest_websocket_messages_sent_total` counter for message volume
- Parse `scrumquest_websocket_messages_received_total` counter for inbound messages
- Calculate bandwidth estimate: (messages_sent + messages_received) * 500 bytes avg * 1.3 safety margin

**Class interface:**
```typescript
export interface ProfilingResults {
  peakRSSMB: number;
  peakHeapMB: number;
  avgHeapMB: number;
  avgCPUPercent: number;
  peakCPUPercent: number;
  eventLoopUtilization: number;   // 0-1 average
  eventLoopPeakUtilization: number;
  eventLoopBlockingDetected: boolean;  // true if any sample > 0.9
  estimatedBandwidthMB: number;
  wsConnectionsPeak: number;
  wsMessagesSent: number;
  wsMessagesReceived: number;
  sampleCount: number;
  durationMs: number;
  samples: Array<MetricSample>;  // raw data for detailed analysis
}

export class MetricsCollector {
  constructor(serverUrl?: string);  // default http://localhost:5000
  start(intervalMs?: number): void;  // default 1000ms
  async stop(): Promise<ProfilingResults>;
  async fetchPrometheusMetrics(): Promise<PrometheusSnapshot>;
}
```

Use Node.js built-in `perf_hooks` for ELU — no external dependencies. Use native `fetch` for Prometheus scraping (Node 18+). Handle fetch failures gracefully (server may not be ready yet during cold start).

CPU% calculation: Convert microsecond delta to percentage of elapsed wall clock time. Formula: `((userDelta + systemDelta) / (elapsedMs * 1000)) * 100`.

Do NOT use any npm packages beyond what's already in the project. This is a standalone profiling utility.

  <action>
Create `tests/profiling/run-profile.ts` — the main profiling orchestrator that runs the full measurement pipeline.

**Orchestration flow:**
1. Parse CLI args: `--users` (default 50), `--duration` (default 60s), `--server-url` (default http://localhost:5000)
2. Verify server is reachable (GET /api/health/livez, retry 3 times with 2s delay)
3. Create MetricsCollector instance
4. Run three profiling scenarios sequentially:

**Scenario A — Cold Start (measure connection storm):**
- Start metrics collection
- Spawn k6: `k6 run --vus {users} --duration 10s tests/load/websocket/game-flow.test.js`
- Stop collection after k6 completes
- Record as `coldStart` results

**Scenario B — Steady State (measure sustained load):**
- Wait 5s for server to stabilize
- Start metrics collection
- Spawn k6: `k6 run --vus {users} --duration {duration}s tests/load/websocket/game-flow.test.js`
- Stop collection after k6 completes
- Record as `steadyState` results

**Scenario C — Teardown (measure cleanup):**
- Start metrics collection (10s monitoring period, no k6)
- Just monitor server metrics as connections drain
- Stop collection after 10s
- Record as `teardown` results

5. Combine results into a single `ProfileReport` object:
```typescript
export interface ProfileReport {
  timestamp: string;  // ISO date
  config: { users: number; duration: number; serverUrl: string };
  scenarios: {
    coldStart: ProfilingResults;
    steadyState: ProfilingResults;
    teardown: ProfilingResults;
  };
  overall: {
    peakRSSMB: number;      // max across all scenarios
    peakHeapMB: number;     // max across all scenarios
    peakCPUPercent: number;  // max across all scenarios
    avgCPUPercent: number;  // weighted avg (steady state dominates)
    eventLoopUtilization: number;  // steady state value
    estimatedBandwidthMBPerMonth: number;  // extrapolated from steady state
    bottlenecks: Array<{ type: string; description: string; severity: 'low' | 'medium' | 'high' }>;
  };
}
```

6. Write JSON results to `tests/reports/profile-YYYY-MM-DD.json`
7. Print summary to stdout

**Bottleneck detection logic:**
- If peakRSS > 400MB: `{ type: 'memory', description: 'Peak RSS exceeds 400MB — may exceed 512MB tier limits', severity: 'high' }`
- If peakCPU > 80%: `{ type: 'cpu', description: 'CPU peaks above 80% — risk of degraded responsiveness', severity: 'high' }`
- If eventLoopUtilization > 0.7: `{ type: 'event-loop', description: 'Event loop >70% utilized — blocking risk under higher load', severity: 'medium' }`
- If eventLoopBlockingDetected: `{ type: 'event-loop-blocking', description: 'Event loop blocking detected (>90% utilization) — investigate synchronous operations', severity: 'high' }`
- If coldStart peakRSS > 1.5x steadyState peakRSS: `{ type: 'cold-start', description: 'Cold start RAM spike 50%+ above steady state — connection storm vulnerable', severity: 'medium' }`

**Bandwidth extrapolation:**
- Calculate from steady state: `(estimatedBandwidthMB / durationSeconds) * 3600 * 730` (730 hours/month)
- Scale by assumed usage: multiply by 0.1 (assume ~10% uptime with active users)

**k6 spawning:** Use `child_process.spawn('k6', [...args])`. Pipe stdout/stderr to process for visibility. Wait for exit code 0. If k6 is not found, print clear error: "k6 not installed. Install from https://k6.io/docs/getting-started/installation/"

**File operations:** Use `fs.mkdirSync('tests/reports', { recursive: true })` before writing.

Script should be runnable via: `npx tsx tests/profiling/run-profile.ts --users 50 --duration 60`
