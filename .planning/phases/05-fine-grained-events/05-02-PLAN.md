  <name>Task 1: Create useEventSync store</name>
  <files>client/src/lib/stores/useEventSync.ts</files>
  <action>
Create client/src/lib/stores/useEventSync.ts - a Zustand store for sequence tracking and event processing.

Interface EventSyncState:
- lastSeq: number (last successfully processed sequence)
- pendingEvents: Map<number, { event: string, data: any }> (out-of-order events waiting)
- isRecovering: boolean (currently fetching missed events)
- pendingOptimistic: Map<string, any> (keyed by action type, stores optimistic state)

Methods:
- handleEvent(event: string, data: any & { seq: number }): boolean
  - If seq === lastSeq + 1: process event, update lastSeq, check pendingEvents for next
  - If seq > lastSeq + 1: gap detected, store in pendingEvents, return false (triggers recovery)
  - If seq <= lastSeq: duplicate/old event, ignore, return true
  - Process any consecutive events from pendingEvents after successful processing

- processEventQueue(): void
  - While pendingEvents has lastSeq + 1: extract, process, increment lastSeq

- requestMissedEvents(socket: Socket, lastSeq: number): void
  - Set isRecovering = true
  - Emit 'request_missed_events' with { lastSeq }

- handleMissedEventsReplay(events: Array<{ event: string, data: any }>): void
  - Process each event in order
  - Set isRecovering = false

- handleFullStateRefresh(lobby: Lobby, seq: number): void
  - Reset lastSeq to provided seq
  - Clear pendingEvents
  - Set isRecovering = false

- setOptimistic(key: string, value: any): void
  - Store in pendingOptimistic map

- clearOptimistic(key: string): void
  - Remove from pendingOptimistic map

- reconcile(key: string, serverValue: any): any
  - Compare pendingOptimistic[key] with serverValue
  - Clear optimistic, return serverValue (or merged if needed)

- reset(): void
  - Reset lastSeq to 0
  - Clear pendingEvents
  - Clear pendingOptimistic
  - Set isRecovering = false

Use Zustand create() with subscribeWithSelector middleware.

  - 'session:player_left' -> handleEvent, then remove player from gameState
  - 'session:host_changed' -> handleEvent, then update hostId in gameState
  - 'session:phase_changed' -> handleEvent, then update gamePhase in gameState
  - 'session:team_changed' -> handleEvent, then update player.team in gameState
  - 'session:avatar_selected' -> handleEvent, then update player.avatar in gameState

- Subscribe to estimation events:
  - 'estimation:vote_cast' -> handleEvent, then update hasSubmittedScore for player
  - 'estimation:votes_revealed' -> handleEvent, then update currentScore for revealed votes
  - 'estimation:consensus_reached' -> handleEvent (state already updated via votes_revealed)
  - 'estimation:timer_started' -> handleEvent, then update currentTimer in gameState
  - 'estimation:timer_paused' -> handleEvent, then update currentTimer.isActive = false
  - 'estimation:timer_resumed' -> handleEvent, then update currentTimer
  - 'estimation:timer_expired' -> handleEvent

- Subscribe to combat events:
  - 'combat:boss_damaged' -> handleEvent, then update boss.currentHealth
  - 'combat:boss_healed' -> handleEvent, then update boss.currentHealth
  - 'combat:boss_defeated' -> handleEvent, then set boss.defeated = true
  - 'combat:player_damaged' -> handleEvent, then update playerCombatStates[playerId].hp
  - 'combat:player_downed' -> handleEvent, then update playerCombatStates[playerId].isDowned
  - 'combat:player_revived' -> handleEvent, then update playerCombatStates[playerId]
  - 'combat:modifier_updated' -> handleEvent, then update battleModifier

- Subscribe to system events:
  - 'system:full_state' -> handleFullStateRefresh
  - 'system:missed_events' -> handleMissedEventsReplay

- Handle gap detection:
  - If handleEvent returns false, call requestMissedEvents(socket, lastSeq)

Each handler should:
1. Call useEventSync.getState().handleEvent()

3. If false (gap), let gap detection logic trigger recovery
