<objective>
Stop the hot battle components from re-rendering on every `setLobby`. Both
`PlayerCharacter.tsx:59` and `PlayerController.tsx:20` use a bare whole-store
`useGameState()` with no selector — Zustand v5 subscribes them to the ENTIRE store, so
every basic attack (which calls setLobby for boss HP) re-renders both components even
when their own state didn't change. `PlayerController` also has no `React.memo` so parent
re-renders always cascade.

Fix: convert to field-scoped selectors — scalar primitives via `useGameState(s => s.field)`;
`useShallow` (from `zustand/react/shallow` — first use in the project) ONLY for multi-field
destructures and object slices that must be selected by identity. Wrap `PlayerController`
in `React.memo`. Add a render-count guardrail test proving a boss-HP change does not
re-render `PlayerCharacter`.

Purpose: Close MAINT-06 — single boss hit no longer re-renders the whole battle tree; no
fresh-object-per-render selectors.
Output: Scoped selectors in both components; React.memo on PlayerController; render-count
perf-guardrail test.
</objective>
