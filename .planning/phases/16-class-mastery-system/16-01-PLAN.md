**GREEN phase:** Create `server/domains/ClassMasteryManager.ts`:

Follow ProgressionManager pattern exactly. Dependencies interface:
```typescript
export interface ClassMasteryManagerDeps {
  eventBus: ScopedEventBus;
  getPlayerClass: (lobbyId: string, playerId: string) => AvatarClass | null;
  getVoters: (lobbyId: string) => string[];
  storage?: IStorage;
  getUserId?: (lobbyId: string, playerId: string) => number | undefined;
}
```

State: `lobbyClassXP = new Map<string, Map<string, Map<AvatarClass, number>>>()` — lobbyId → playerId → class → XP

Event subscriptions (same events as ProgressionManager):
- `estimation:vote_cast` → award CLASS_XP_RATES.vote to player's current class
- `combat:boss_damaged` → award damage * CLASS_XP_RATES.boss_damage to player's current class
- `estimation:full_consensus_reached` → award CLASS_XP_RATES.consensus to all voters' current classes
- `combat:player_revived` → award CLASS_XP_RATES.revival to reviver's current class

Key methods:
- `awardClassXP(lobbyId, playerId, avatarClass, amount, source)` — tracks XP, emits events, checks tier-up, persists fire-and-forget
- `getClassXP(lobbyId, playerId, avatarClass)` → number
- `getMasteryTier(lobbyId, playerId, avatarClass)` → MasteryTier
- `getMasteryMultiplier(lobbyId, playerId, avatarClass)` → number (the stat multiplier)
- `getUnlockedAbilities(lobbyId, playerId, avatarClass)` → string[]
- `initializeClassMastery(lobbyId, playerId, avatarClass, startingXP)` — silent init
- `loadAllClassMastery(lobbyId, playerId, userId)` — load from storage
- `cleanupLobby(lobbyId)` — remove lobby data

Persistence: fire-and-forget pattern (same as ProgressionManager). Will need IStorage extension (to be wired in Plan 16-02).

For now, the storage methods (`getClassMastery`, `updateClassMastery`, `getAllClassMastery`) can be called if storage exists, but the actual IStorage interface extension happens in Plan 16-02.
