<objective>
MAINT-08: Route ALL revival traffic through CombatManager (removing both redundant 100ms watchdogs), and replace the disconnect-sweeper's naked io.to().emit('host_transferred') with a proper eventBus event (session:host_transferred) bridged through ClientEventEmitter to the existing wire event.

Purpose: After Phase 49, CombatManager owns a fully self-managing, event-driven revival lifecycle (per-session 100ms setInterval that emits combat:revival_started/progress/player_revived/cancelled). The two external 100ms polling loops (gameState.ts revivalWatchdog + websocket.ts revivalWatchdogInterval) are now redundant dead polls. Separately, the disconnect sweeper is the ONLY place websocket.ts directly calls io.to().emit() for a domain event — every other domain event flows through the eventBus → ClientEventEmitter bridge. This plan brings host-transfer onto that bridge and consolidates revival.

Output: revive_start/cancel routed to CombatManager; revive_tick handler removed; both watchdogs + dead GameState revival methods deleted; session:host_transferred event + bridge added; sweeper io.to() removed.

SEQUENCING: depends_on 50-01 (both plans modify gameState.ts and websocket.ts — NOT parallel-safe). Within this plan: add the additive event plumbing FIRST (eventTypes → bridge → SessionManager emit), then the point-of-no-return deletions (sweeper io.to(), revive handlers, watchdogs, GameState revival methods).

WIRE-NAME GUARD: The bridge MUST emit the wire name 'host_transferred' (NOT 'session:host_transferred'). GamePage.tsx:232 listens on 'host_transferred'. This is distinct from session:host_changed (Pitfall 4) — do NOT conflate.
</objective>
