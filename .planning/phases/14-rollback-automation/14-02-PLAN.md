   - Extract sync status: `.status.sync.status`

5. **Check health endpoint:**
   - continue-on-error: true
   - Get health URL from vars
   - curl and check for HTTP 200
   - Output status code

6. **Trigger rollback if unhealthy:**

     - component: '' (all)
     - dry_run: 'false'
     - reason: Auto-generated with health/sync status

- Production auto-rollback is DISABLED per CONTEXT.md decision
- Use core.warning() for production alerts
- Use core.notice() for triggered auto-rollbacks
- Secrets: ARGOCD_AUTH_TOKEN, GITHUB_TOKEN

**Environment detection workaround:**
Since workflow_run doesn't expose inputs, use this logic:
- If workflow_run was from push event -> dev (deploy.yml only deploys dev on push)
- If workflow_run was from workflow_dispatch -> need to infer
- Simplest: Add a step that queries the triggering run's job summary or use repository dispatch

For this implementation, use the simpler approach:
- Push to main = dev deployment
- workflow_dispatch = need to check artifacts or assume it was passed correctly

Actually, looking at deploy.yml more closely:
- Push triggers deploy-dev only
- workflow_dispatch can trigger any environment

The workflow_run event gives us `github.event.workflow_run.event` which tells us if it was 'push' or 'workflow_dispatch'. If push, it's dev. If workflow_dispatch, we can query the run for its inputs.

Implement environment detection:
```yaml
- name: Determine environment
  id: get-env
  uses: actions/github-script@v6
  with:
    script: |
      const runEvent = '${{ github.event.workflow_run.event }}';
      if (runEvent === 'push') {
        return 'dev';
      }
      // For workflow_dispatch, query the workflow run
      const run = await github.rest.actions.getWorkflowRun({
        owner: context.repo.owner,
        repo: context.repo.repo,
        run_id: ${{ github.event.workflow_run.id }}
      });
      return run.data.inputs?.environment || 'dev';
    result-encoding: string
```

**Create audit directory:**

**Add to rollback.yml - new job: audit-and-notify**
This job runs after successful rollback to:
1. Commit audit log entry
2. Post comment on rolled-back commit

```yaml
audit-and-notify:
  name: Record Audit Trail
  runs-on: ubuntu-latest
  needs: rollback
  if: needs.rollback.outputs.rollback-success == 'true' && github.event.inputs.dry_run == 'false'
  permissions:
    contents: write  # For git push
    pull-requests: write  # For PR comments

  steps:
    - name: Checkout
      uses: actions/checkout@v4
      with:
        token: ${{ secrets.GITHUB_TOKEN }}

    - name: Record rollback in audit log
      run: |
        mkdir -p .argocd-rollback

        # Create JSONL audit entry (one line, valid JSON)
        ENTRY=$(jq -nc \
          --arg ts "$(date -Iseconds)" \
          --arg env "${{ github.event.inputs.environment }}" \
          --arg comp "${{ github.event.inputs.component || 'all' }}" \
          --arg trigger "manual" \
          --arg actor "${{ github.actor }}" \
          --arg from "${{ needs.rollback.outputs.from-revision }}" \
          --arg to "${{ needs.rollback.outputs.to-revision }}" \
          --arg id "${{ needs.rollback.outputs.to-deployment-id }}" \
          --arg reason "${{ github.event.inputs.reason }}" \
          --arg run "${{ github.server_url }}/${{ github.repository }}/actions/runs/${{ github.run_id }}" \
          --argjson duration "${{ needs.rollback.outputs.duration || 0 }}" \
          '{timestamp: $ts, environment: $env, component: $comp, trigger: $trigger, actor: $actor, from_revision: $from, to_revision: $to, to_deployment_id: $id, reason: $reason, workflow_run: $run, duration_seconds: $duration, success: true}')

        echo "$ENTRY" >> .argocd-rollback/rollback-history.jsonl

        # Commit audit log
        git config user.name "github-actions[bot]"
        git config user.email "github-actions[bot]@users.noreply.github.com"
        git add .argocd-rollback/rollback-history.jsonl
        git diff --cached --quiet || git commit -m "audit: rollback ${{ github.event.inputs.environment }} to ${{ needs.rollback.outputs.to-revision }}"
        git push

    - name: Post comment on rolled-back commit
      uses: peter-evans/commit-comment@v3
      with:
        sha: ${{ needs.rollback.outputs.from-revision }}
        body: |
          ## Rollback Notification

          This commit was rolled back in **${{ github.event.inputs.environment }}** environment.

          | Detail | Value |
          |--------|-------|
          | **Rolled back to** | `${{ needs.rollback.outputs.to-revision }}` |
          | **Reason** | ${{ github.event.inputs.reason }} |
          | **Triggered by** | @${{ github.actor }} |
          | **Workflow run** | [${{ github.run_id }}](${{ github.server_url }}/${{ github.repository }}/actions/runs/${{ github.run_id }}) |

          Please investigate the root cause before attempting to redeploy.
```

Update auto-rollback-monitor.yml to record audit entries for auto-triggered rollbacks.

When the auto-rollback-monitor triggers a rollback, it should also record an audit entry (separate from the rollback.yml audit, which records manual rollbacks).

**Add after the rollback trigger step:**

```yaml
- name: Record auto-rollback trigger
  if: |
    steps.argocd-check.outputs.health != 'Healthy' ||
    steps.argocd-check.outputs.sync == 'OutOfSync' ||
    steps.health-endpoint.outputs.status != '200'
  run: |
    # Clone repo to record audit
    git clone --depth 1 https://x-access-token:${{ secrets.GITHUB_TOKEN }}@github.com/${{ github.repository }}.git audit-temp
    cd audit-temp

    mkdir -p .argocd-rollback

    ENTRY=$(jq -nc \
      --arg ts "$(date -Iseconds)" \
      --arg env "${{ steps.get-env.outputs.result }}" \
      --arg trigger "auto" \
      --arg actor "github-actions[bot]" \
      --arg health "${{ steps.argocd-check.outputs.health }}" \
      --arg sync "${{ steps.argocd-check.outputs.sync }}" \
      --arg http "${{ steps.health-endpoint.outputs.status }}" \
      --arg deploy_run "${{ github.event.workflow_run.html_url }}" \
      '{timestamp: $ts, environment: $env, trigger: $trigger, actor: $actor, health_status: $health, sync_status: $sync, http_status: $http, triggered_by_deploy: $deploy_run, reason: "Auto-rollback triggered due to health check failure"}')

    echo "$ENTRY" >> .argocd-rollback/auto-rollback-triggers.jsonl

    git config user.name "github-actions[bot]"
    git config user.email "github-actions[bot]@users.noreply.github.com"
    git add .argocd-rollback/auto-rollback-triggers.jsonl
    git diff --cached --quiet || git commit -m "audit: auto-rollback triggered for ${{ steps.get-env.outputs.result }}"
    git push
```

**Note:** The actual rollback execution (triggered via workflow_dispatch) will create its own entry in rollback-history.jsonl. This auto-rollback-triggers.jsonl captures:
- When auto-rollback was TRIGGERED (not the result)
- The health/sync status that caused the trigger
- Link to the deploy workflow run that caused the issue

This creates two audit files:
1. `.argocd-rollback/rollback-history.jsonl` - All rollback executions (manual and auto)
2. `.argocd-rollback/auto-rollback-triggers.jsonl` - Auto-rollback trigger events only
