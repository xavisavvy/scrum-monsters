<task type="auto">
  <name>Task 2: Create unified rollback workflow</name>
  <files>.github/workflows/rollback.yml</files>
  <action>
Create rollback.yml implementing the unified rollback pattern from research. Key components:

**Workflow triggers:**
- workflow_dispatch with inputs:
  - environment (required, choice: dev/staging/prod)
  - component (optional, choice: blank for all, or 'app')
  - dry_run (boolean, default false)
  - reason (required, string)

**Concurrency:**
- group: rollback-${{ github.event.inputs.environment }}
- cancel-in-progress: false (never cancel active rollback)

**Environment variables:**
- ARGOCD_SERVER: argocd.local (matches deploy.yml)

**Jobs:**

1. **rate-limit-check** job:
   - Checkout repo
   - Read state file `.argocd-rollback/rollback-state-{env}.json`
   - Check 15-minute cooldown
   - Check rate limit: 3 rollbacks per hour max
   - Initialize state file if doesn't exist (use jq)
   - Output: rate-check=passed or fail with error

2. **rollback** job:
   - needs: rate-limit-check
   - environment mapping:
     - prod -> production (requires approval)
     - staging -> staging
     - dev -> development
   - Use expression: `${{ github.event.inputs.environment == 'prod' && 'production' || (github.event.inputs.environment == 'staging' && 'staging' || 'development') }}`

   Steps:
   a. Checkout
   b. Install ArgoCD CLI v2.13.3 (curl from GitHub releases, same as deploy.yml)
   c. Get current deployment info (argocd app get, extract revision/health/sync)
   d. Get rollback target (argocd app history -o json, extract [1] for N-1)
   e. If dry_run: Generate preview Job Summary and exit
   f. Disable auto-sync: `argocd app set APP --sync-policy none`
   g. Execute rollback with retry logic (2 attempts max, 10s sleep between):
      `argocd app rollback APP ID --timeout 600`
   h. Wait for health: `argocd app wait APP --health --sync --timeout 300`
   i. Verify health endpoint (sleep 120, curl health URL)
   j. Re-enable auto-sync for dev only: `argocd app set APP --sync-policy automated`
   k. Update rate limit state file
   l. Generate success Job Summary

**Outputs for downstream jobs:**
- rollback-success: true/false
- from-revision: original revision
- to-revision: rolled back revision
- to-deployment-id: ArgoCD deployment ID

**Critical patterns from research:**
- Use ARGOCD_AUTH_TOKEN secret (not hardcoded)
- Use --grpc-web flag for ArgoCD CLI
- Health URL from vars: `${{ vars[format('{0}_HEALTH_URL', inputs.environment)] }}`
- All echo outputs use >> "$GITHUB_OUTPUT"
- Use heredoc for Job Summary (cat >> "$GITHUB_STEP_SUMMARY")

**Rate limit state file format:**
```json
{
  "last_rollback": "2026-02-03T10:30:00Z",
  "rollback_count_1h": 1,
  "rollback_count_24h": 3
}
```

Avoid these pitfalls from research:
- Do NOT leave auto-sync disabled forever (re-enable for dev)
- Do NOT skip the 2-minute health stabilization wait
- Do NOT use deprecated set-output (use $GITHUB_OUTPUT)
