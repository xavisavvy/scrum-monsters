  <files>.github/workflows/ci.yml</files>
  <action>
Update `.github/workflows/ci.yml` to add coverage reporting:

1. Add `pull-requests: write` permission to the test job (required for coverage comments):
```yaml
test:
  name: Test
  runs-on: ubuntu-latest
  timeout-minutes: 15
  permissions:
    contents: read
    pull-requests: write
```

2. Modify the test job to use coverage flag directly (remove duplicate test run):
   - Remove the plain `npm test` step
   - Keep `npm run test:coverage` but remove `continue-on-error: true` (thresholds should now pass)
   - Change to: `run: npx vitest run --coverage.enabled true`

3. Add coverage report action after tests (for PR comments):
```yaml
- name: Report Coverage
  if: always() && github.event_name == 'pull_request'
  uses: davelosert/vitest-coverage-report-action@v2
  with:
    file-coverage-mode: changes
```

4. Add a new job for updating coverage badge (only on main branch):
```yaml
update-coverage-badge:
  name: Update Coverage Badge
  runs-on: ubuntu-latest
  needs: [test]
  if: github.ref == 'refs/heads/main' && github.event_name == 'push'

  steps:
    - name: Checkout
      uses: actions/checkout@v4

    - name: Download coverage artifact
      uses: actions/download-artifact@v4
      with:
        name: coverage-report
        path: coverage

    - name: Extract coverage percentage
      id: coverage
      run: |
        COVERAGE=$(jq '.total.lines.pct' coverage/coverage-summary.json)
        echo "percentage=$COVERAGE" >> $GITHUB_OUTPUT

    - name: Update coverage badge
      uses: schneegans/dynamic-badges-action@v1.7.0
      with:
        auth: ${{ secrets.GIST_SECRET }}
        gistID: PLACEHOLDER_GIST_ID
        filename: coverage.json
        label: coverage
        message: ${{ steps.coverage.outputs.percentage }}%
        valColorRange: ${{ steps.coverage.outputs.percentage }}
        maxColorRange: 90
        minColorRange: 50
```

Note: The gistID is a placeholder - user will update after creating gist during branch protection setup.

5. Keep the existing artifact upload step (coverage report action and badge job use it).

Important: Do NOT modify other jobs (lint-and-typecheck, build, security-audit, ci-success).

<task type="checkpoint:human-action" gate="blocking">
  <name>Task 2: Configure Branch Protection Rules</name>
  <what-to-configure>
GitHub branch protection rules must be configured via the repository settings UI. Claude cannot access the GitHub Settings API for branch protection.
  </what-to-configure>
  <instructions>
**Step 1: Create Coverage Badge Gist**
1. Go to https://gist.github.com
2. Create a new PUBLIC gist
3. Filename: `coverage.json`
4. Content: `{"schemaVersion":1,"label":"coverage","message":"0%","color":"red"}`
5. Save and copy the gist ID from the URL (the long alphanumeric string)
6. Update `.github/workflows/ci.yml` - replace `PLACEHOLDER_GIST_ID` with your gist ID

**Step 2: Create Personal Access Token for Gist**
1. Go to GitHub Settings -> Developer settings -> Personal access tokens -> Tokens (classic)
2. Generate new token with only the `gist` scope
3. Copy the token

**Step 3: Add Repository Secret**
1. Go to Repository Settings -> Secrets and variables -> Actions
2. Click "New repository secret"
3. Name: `GIST_SECRET`
4. Value: paste the token from Step 2
5. Save

**Step 4: Configure Branch Protection**
1. Go to Repository Settings -> Branches
2. Click "Add branch protection rule" (or edit existing for `main`)
3. Branch name pattern: `main`
4. Enable these settings:

**Require a pull request before merging:**
- [x] Require approvals: 1
- [x] Dismiss stale pull request approvals when new commits are pushed
- [x] Require review from Code Owners (optional - enables CODEOWNERS auto-assignment)

**Require status checks to pass before merging:**
- [x] Require branches to be up to date before merging
- Required status checks (search and add):
  - `CI Success`
  - `Validate PR Title`

**Additional settings:**
- [x] Require linear history (enables squash merge only)
- [ ] Do not allow bypassing the above settings (or allow for emergency - your choice)

5. Click "Create" or "Save changes"

**Step 5: Configure Merge Settings (optional but recommended)**
1. Go to Repository Settings -> General -> Pull Requests
2. Under "Allow merge commits":
   - [x] Allow squash merging (keep enabled)
   - [ ] Allow merge commits (disable for linear history)
   - [ ] Allow rebase merging (disable for linear history)
3. [x] Default to squash merge
4. [x] Default commit message: Pull request title

**Step 6: Add Coverage Badge to README (optional)**
Add this markdown to README.md:
```markdown
![Coverage](https://img.shields.io/endpoint?url=https://gist.githubusercontent.com/Preston/YOUR_GIST_ID/raw/coverage.json)
```
