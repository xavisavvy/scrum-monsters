  <name>Task 1: Wire /metrics endpoint and fix cardinality in metrics module</name>
  <files>server/routes.ts, server/metrics.ts, server/websocket.ts</files>
  <action>
1. In `server/routes.ts`:
   - Add import: `import { getMetrics, getMetricsContentType, metricsMiddleware } from "./metrics.js";`
   - Add `/metrics` GET route BEFORE the rate limiter middleware (metrics should not be rate-limited, Prometheus needs reliable access). Place it right after `const httpServer = createServer(app);`:
     ```typescript
     app.get('/metrics', async (_req, res) => {
       try {
         res.set('Content-Type', getMetricsContentType());
         res.end(await getMetrics());
       } catch (err) {
         res.status(500).end(String(err));
       }
     });
     ```
   - Add `app.use(metricsMiddleware());` right after the `/metrics` route (so /metrics itself is not measured, avoiding self-referential noise).

2. In `server/metrics.ts`, fix the `metricsMiddleware()` function to prevent high-cardinality label explosion:
   - Replace `const route = req.route?.path || req.path;` with a `normalizeRoute(req)` call.
   - Add `normalizeRoute` function before the middleware:
     ```typescript
     function normalizeRoute(req: any): string {
       if (req.route?.path) return req.route.path;
       const path: string = req.path;
       if (path.startsWith('/join/')) return '/join/:lobbyId';
       if (path.startsWith('/room/')) return '/room/:roomId';
       if (path.startsWith('/assets/')) return '/assets/*';
       if (path.match(/\.(js|css|png|jpg|svg|woff2?|ico|map|json)$/)) return '/static/*';
       if (path === '/') return '/';
       if (path.startsWith('/api/')) return path;  // API routes are fixed, safe
       return '/other';  // Catch-all for SPA routes served by Vite
     }
     ```

3. In `server/websocket.ts`:
   - Add import: `import { updateWebsocketMetrics, updateLobbyMetrics, updatePlayerMetrics } from "./metrics.js";`
   - In the `io.on('connection')` handler, after `socketLogger.info(...)` for new connection, add: `updateWebsocketMetrics(io.sockets.sockets.size);`
   - In the `disconnect` handler, add: `updateWebsocketMetrics(io.sockets.sockets.size);`
   - Note: Lobby and player metric updates are more complex (they happen in domain managers). For now, WebSocket connection count is the critical gauge. Lobby/player counts already have helper functions if domain code is updated later.
  </action>
