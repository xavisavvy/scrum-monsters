    1. **Install React Router v7 (declarative mode):**
       ```bash

       ```
       This replaces react-router-dom v6 with the unified react-router v7 package. Declarative mode (NOT framework mode) -- no react-router.config.ts, no CLI changes, no build changes.

    2. **Create `client/src/routes.tsx`** with `createBrowserRouter`:
       ```typescript
       import { createBrowserRouter, Navigate, redirect } from 'react-router';
       ```
       Define routes:
       - `/` -> LandingRoute (wraps existing LandingPage component)
       - `/about` -> AboutRoute (wraps existing AboutPage)
       - `/features` -> FeaturesRoute (wraps existing FeaturesPage)
       - `/pricing` -> PricingRoute (wraps existing PricingPage)
       - `/support` -> SupportRoute (wraps existing SupportPage)
       - `/play` -> MenuPage (the current 'menu' state -- game menu with create/join)
       - `/game/:lobbyId` -> GamePage (handles all game phases: avatar_selection, lobby, battle)
       - `/room/:roomId` -> RoomPage (recurring meeting room join -- can reuse existing RoomJoin)
       - `*` -> Redirect to `/`

       Add a loader on the root route (or a redirect route) that handles legacy query params:
       - `?join=ABC123` -> redirect to `/game/ABC123`
       - `?room=xyz` -> redirect to `/room/xyz`
       - `?game=menu` -> redirect to `/play`
       - `?page=about` -> redirect to `/about` (etc.)

       Use `loader` functions for redirects:
       ```typescript
       {
         path: '/',
         loader: ({ request }) => {
           const url = new URL(request.url);
           const join = url.searchParams.get('join');
           if (join) return redirect(`/game/${join}`);
           const room = url.searchParams.get('room');
           if (room) return redirect(`/room/${room}`);
           // ... etc
           return null;
         },
         element: <LandingRoute />
       }
       ```

    3. **Create thin route wrapper components** in `client/src/pages/`:
       Each marketing route wrapper imports the existing component from `@/components/marketing/` and provides navigation via `useNavigate()` from react-router instead of the `onNavigate` callback prop.

       For example, `LandingRoute.tsx`:
       ```typescript
       import { useNavigate } from 'react-router';
       import { LandingPage } from '@/components/marketing/LandingPage';
       export default function LandingRoute() {
         const navigate = useNavigate();
         return <LandingPage onStartGame={() => navigate('/play')} onNavigate={(page) => navigate(`/${page === 'landing' ? '' : page}`)} />;
       }
       ```

       Similarly for AboutRoute, FeaturesRoute, PricingRoute, SupportRoute.

       For `MenuPage.tsx`: Extract the 'menu' case from App.tsx's renderCurrentState() into its own component. It needs access to audio, last lobby, WebSocket, etc. Move the menu rendering logic there, using `useNavigate()` for navigation (e.g., navigate('/game/create'), navigate('/game/join')).

       For `GamePage.tsx`: This is the critical route. It:
       - Reads `lobbyId` from `useParams()`
       - Contains the WebSocket connection logic, event handlers, and game phase rendering
       - Renders the appropriate component based on server-driven game phase (lobby, avatar_selection, battle)
       - Does NOT change the URL when game phase changes (ROUTE-06)

    4. **Update `client/src/main.tsx`:**
       Replace `<App />` with `<RouterProvider router={router} />` where `router` is imported from routes.tsx.

    5. **Refactor `client/src/App.tsx`:**
       App.tsx becomes much simpler. It should be a layout component that wraps all routes:
       - Keep: WebSocket connection setup, audio initialization, CSRF token fetch, auth check, developer menu, cheat menu, reconnection status/dialog, toaster
       - Remove: The entire `appState` state machine, `renderCurrentState()` switch, all the inline navigation logic
       - The route content renders via `<Outlet />` from react-router

       Structure App.tsx as a layout:
       ```tsx
       function App() {
         // Keep all the useEffect hooks for WebSocket, audio, auth
         // Keep overlay components (DeveloperMenu, CheatMenu, ReconnectionStatus, etc.)
         return (
           <div className="retro-container">
             <Outlet />
             <DeveloperMenu ... />
             <CheatMenu ... />
             <ReconnectionStatus />
             <ConnectionIndicator />
             <ReconnectionDialog ... />
             <Toaster />
           </div>
         );
       }
       ```

       Use App as the root route's element in routes.tsx. Child routes render inside `<Outlet />`.

    6. **Handle OAuth redirect params:** Currently App.tsx checks for `?auth=success&provider=xxx` query params. Move this logic into a shared hook or keep it in App.tsx (the layout) since it applies globally. Use `useSearchParams()` from react-router instead of `window.location.search`.

    7. **Navigation links in marketing pages:** The existing marketing pages use `onNavigate` callback prop. The route wrappers translate this to `navigate()` calls. The existing components do NOT need modification -- the route wrappers handle the translation.
