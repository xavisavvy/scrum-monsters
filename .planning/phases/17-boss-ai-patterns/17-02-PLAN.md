Create `server/domains/boss-ai/BossAI.ts` — the coordinator that owns all three subsystems (BossStateMachine, PatternSequencer, ThreatEvaluator) and provides a simple API for CombatManager to call.

**BossAI class:**

Constructor: `BossAI(bossType: BossType)` — looks up behavior from BOSS_BEHAVIORS, creates internal BossStateMachine, PatternSequencer, and ThreatEvaluator instances. Stores `lastPatternId: string | null` for anti-repeat.

**Public methods:**

1. `selectNextAction(context: BattleContext, threatTable: Map<string, ThreatEntry>, alivePlayers: string[]): BossAction | null`
   - Get current phase from `BossStateMachine.getCurrentPhase(context.bossHp, context.bossMaxHp)`
   - Get available patterns from PatternSequencer filtered by phase
   - Select pattern via PatternSequencer (passing lastPatternId for anti-repeat)
   - If no pattern available, return null
   - Determine target(s) based on pattern.targetMode:
     - `highest_threat`: use ThreatEvaluator.selectTarget (but force top threat)
     - `lowest_hp`: iterate alive players, pick lowest HP
     - `random`: random from alive players
     - `all`: all alive players
     - `multi`: pick N random from alive players (with pattern.targetCount)
   - Update lastPatternId
   - Return `BossAction { pattern, targetPlayerIds }`

2. `checkPhaseTransition(hp: number, maxHp: number): { transitioned: boolean; newPhase: BossPhaseNumber; message: string | null }`
   - Delegates to BossStateMachine.checkPhaseTransition
   - If transitioned, returns the phase transition message from behavior definition
   - Tracks lastPhase internally to ensure one-way transitions

3. `getBossType(): BossType`

4. `getBehavior(): BossBehavior`

5. `recordThreat(threatTable: Map<string, ThreatEntry>, playerId: string, actionType: 'damage' | 'healing' | 'revival', amount: number): void`
   - Delegates to ThreatEvaluator.addThreat

6. `cleanupPlayer(threatTable: Map<string, ThreatEntry>, playerId: string): void`
   - Delegates to ThreatEvaluator.cleanupPlayer
