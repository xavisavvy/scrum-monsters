<task type="auto">
  <name>Task 1: Generate SSH deploy key and create IAM trust policy JSON</name>
  <files><!-- system files outside repo: ~/.ssh/github-actions-deploy, ~/.ssh/github-actions-deploy.pub --></files>
  <action>
Generate the artifacts the user will need for the manual provisioning steps:

1. **Generate a dedicated SSH deploy key** (no passphrase) for GitHub Actions:
   ```bash
   ssh-keygen -t ed25519 -C "github-actions-deploy" -f ~/.ssh/github-actions-deploy -N ""
   ```
   Display the public key so the user can add it to the VPS, and the private key so the user can paste it into GitHub secrets.

2. **Look up the AWS account ID:**
   ```bash
   aws sts get-caller-identity --query Account --output text
   ```
   If AWS CLI is not configured locally, instruct the user to run this on the VPS or in AWS Console (top-right corner, account ID).

3. **Generate the IAM trust policy JSON** using the account ID:
   ```json
   {
     "Version": "2012-10-17",
     "Statement": [
       {
         "Effect": "Allow",
         "Principal": {
           "Federated": "arn:aws:iam::ACCOUNT_ID:oidc-provider/token.actions.githubusercontent.com"
         },
         "Action": "sts:AssumeRoleWithWebIdentity",
         "Condition": {
           "StringEquals": {
             "token.actions.githubusercontent.com:aud": "sts.amazonaws.com"
           },
           "StringLike": {
             "token.actions.githubusercontent.com:sub": "repo:xavisavvy/scrum-monsters:*"
           }
         }
       }
     ]
   }
   ```
   Note: `StringLike` with `*` allows any ref (main branch pushes and workflow_dispatch). Strictly scoping to `ref:refs/heads/main` may block workflow_dispatch which uses a different sub format.

4. **Print clear instructions** for the user listing what they need to do in the checkpoint.
  </action>
  <verify>
SSH key files exist: `ls -la ~/.ssh/github-actions-deploy ~/.ssh/github-actions-deploy.pub`.
Trust policy JSON is valid: pipe the JSON through `python -c "import json,sys; json.load(sys.stdin)"`.
  </verify>
  <done>SSH deploy key pair generated at ~/.ssh/github-actions-deploy, IAM trust policy JSON prepared with correct repo scope, AWS account ID retrieved (or instructions printed for user to retrieve it).</done>

<task type="checkpoint:human-action" gate="blocking">
  <name>Task 2: Provision AWS OIDC, IAM role, SSH key on VPS, and GitHub secrets</name>
  <action>The user must complete the following manual steps using the artifacts generated in Task 1.</action>
  <instructions>
**A. Add SSH deploy key to VPS:**
1. SSH into the VPS: `ssh -i ~/.ssh/lightsail_scrummonsters ubuntu@34.199.135.244`
2. Append the public key to authorized_keys:
   ```bash
   echo "PASTE_PUBLIC_KEY_HERE" >> ~/.ssh/authorized_keys
   ```
3. Exit the VPS
4. Test the new key works: `ssh -i ~/.ssh/github-actions-deploy ubuntu@34.199.135.244 "echo connected"`

**B. Create AWS OIDC Identity Provider** (skip if already exists):
1. Go to AWS Console > IAM > Identity providers > Add provider
2. Provider type: OpenID Connect
3. Provider URL: `https://token.actions.githubusercontent.com`
4. Audience: `sts.amazonaws.com`
5. Click "Add provider"

**C. Create IAM Role for GitHub Actions:**
1. Go to IAM > Roles > Create role
2. Trusted entity type: Web identity
3. Identity provider: `token.actions.githubusercontent.com`
4. Audience: `sts.amazonaws.com`
5. Click Next
6. Do NOT attach any permissions policies (the role only needs to exist for OIDC proof; actual AWS operations use the existing backup IAM user credentials on the VPS)
7. Role name: `github-actions-scrummonsters`
8. Click "Create role"
9. After creation, go to the role > Trust relationships > Edit trust policy
10. Replace with the trust policy JSON from Task 1 (ensures repo scoping)
11. Copy the Role ARN (e.g., `arn:aws:iam::123456789012:role/github-actions-scrummonsters`)

**D. Add GitHub Repo Secrets:**
1. Go to GitHub repo > Settings > Secrets and variables > Actions > New repository secret
2. Add `SSH_PRIVATE_KEY`: paste the entire contents of `~/.ssh/github-actions-deploy` (the private key file)
3. Add `AWS_OIDC_ROLE_ARN`: paste the IAM role ARN from step C.11

**E. Create GitHub Environments:**
1. Go to GitHub repo > Settings > Environments > New environment
2. Create environment named `staging` (no protection rules needed)
3. Create environment named `production` (optionally add yourself as required reviewer for extra safety, but workflow_dispatch already provides manual gating)
  </instructions>
  <resume-signal>Type "provisioned" when all five sections (A-E) are complete, or describe any issues encountered.</resume-signal>
