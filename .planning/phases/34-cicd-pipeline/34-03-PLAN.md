  <name>Task 1: Trigger staging deploy by pushing to main and verify drizzle-kit push non-interactive behavior</name>
  <files></files>
  <action>
1. **Verify drizzle-kit push works non-interactively** before relying on it in CI:
   - Check if the `db:push` npm script in package.json passes `--force` or if drizzle-kit push hangs waiting for confirmation in non-interactive mode
   - If `drizzle-kit push` does NOT have a `--force` flag in the npm script and might prompt, update the SSH deploy script in `.github/workflows/deploy-lightsail.yml` to use `npx drizzle-kit push --force` instead of `npm run db:push` (or update the npm script itself)
   - If drizzle-kit push is confirmed non-interactive by default (no destructive changes pending), leave as-is

2. **Push current changes to main** to trigger the pipeline:
   - Ensure all Plan 01 changes are committed and pushed to main
   - This push triggers `docker.yml` (build + push to GHCR)
   - After `docker.yml` completes, `deploy-lightsail.yml` should auto-trigger via `workflow_run`

3. **Monitor the GitHub Actions run:**
   - Use `gh run list --workflow=docker.yml --limit=1` to check docker.yml status
   - Use `gh run list --workflow=deploy-lightsail.yml --limit=1` to check deploy workflow status
   - Wait for both to complete

4. **Check for any workflow errors** and diagnose:
   - If docker.yml fails: check build logs with `gh run view --log`
   - If deploy-lightsail.yml fails: check which job failed (deploy-staging, smoke-test)
   - If OIDC fails: likely `id-token: write` permission issue or IAM trust policy mismatch
   - If SSH fails: likely key format or permissions issue in the GitHub secret
   - If smoke test fails: likely BASE_URL not reaching the app or Playwright browser issue
  </action>

  </verify>
