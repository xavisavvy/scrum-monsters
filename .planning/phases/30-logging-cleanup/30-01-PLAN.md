Migrate all console.log/warn/error calls in these 4 files to the appropriate Pino logger. These files contain ~183 of the 229 server console statements.

**Mapping rules:**

1. **server/websocket.ts** (119 statements) → use `socketLogger` for connection/event handling:
   - `import { socketLogger, gameLogger, authLogger } from './logger.js';`
   - `console.log(...)` → `socketLogger.info(...)` or `socketLogger.debug(...)` for verbose messages
   - `console.error(...)` → `socketLogger.error(...)`
   - `console.warn(...)` → `socketLogger.warn(...)`
   - For structured data, use object-first format: `socketLogger.info({ playerId, lobbyId, transport }, 'Player connected')` instead of template literals
   - Connection statistics block (lines ~200-211) → `socketLogger.info({ totalConnections, activeConnections, hostConnections, activeLobbies, disconnectReasons }, 'Connection statistics')`
   - Player connected block (lines ~243-251) → single `socketLogger.info({ socketId, transport, ip, userAgent, activeConnections, authenticated, userId }, 'Player connected')`
   - Player disconnected block (lines ~2063-2067) → single `socketLogger.info({ socketId, reason, isHost, lobbyId, activeConnections }, 'Player disconnected')`

2. **server/gameState.ts** (31 statements) → use `gameLogger`:
   - `import { gameLogger } from './logger.js';`
   - All game state logs → `gameLogger.info(...)` or `gameLogger.debug(...)`
   - Error logs → `gameLogger.error(...)`
   - Token validation logs → `gameLogger.debug(...)` (verbose, not needed in production)
   - Use structured format: `gameLogger.info({ playerId, lobbyId, phase }, 'Phase transition')` instead of template literals with emojis

3. **server/index.ts** (17 statements) → use `httpLogger` for server lifecycle, `dbLogger` for database:
   - `import { httpLogger, dbLogger } from './logger.js';`
   - Server startup messages → `httpLogger.info(...)`
   - Unhandled rejection/uncaught exception → `httpLogger.fatal(...)`
   - Database connection close → `dbLogger.info('Database connections closed')`
   - Shutdown messages → `httpLogger.info({ signal }, 'Graceful shutdown initiated')`
   - Server timeout config → `httpLogger.info({ keepAlive, headers, request }, 'Server timeouts configured')`
   - **IMPORTANT**: The `connect-pg-simple` store config at line ~54 uses `errorLog: console.error.bind(console)` — replace with `errorLog: dbLogger.error.bind(dbLogger)`

4. **server/redis.ts** (16 statements) → use `dbLogger`:
   - `import { dbLogger } from './logger.js';`
   - All Redis connection/init logs → `dbLogger.info(...)`
   - All Redis error logs → `dbLogger.error({ err: error }, 'Redis cache error')`
   - Redis close → `dbLogger.info('Redis connection closed')`

**Key conventions:**
- Strip emoji prefixes from log messages (emojis don't belong in structured logs)
- Use Pino's object-first API: `logger.info({ key: value }, 'message')` — NOT template literals
- Use `debug` level for verbose/diagnostic messages (token validation, heartbeats, movement)
- Use `info` level for operational events (connection, disconnection, lobby create/join, phase transitions)
- Use `warn` level for concerning but non-fatal situations
- Use `error` level for failures that need investigation
- Use `fatal` level for unrecoverable errors (uncaught exceptions, unhandled rejections)
- For error objects, pass as `{ err: error }` (Pino's standard error serialization field)
