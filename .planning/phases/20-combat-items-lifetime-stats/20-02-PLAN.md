  <action>
Follow ProgressionManager.ts pattern for event subscriptions and fire-and-forget persistence. TDD: write failing tests first.

**StatsTrackerDeps interface:**
- eventBus: ScopedEventBus
- storage: IStorage | null (nullable for in-memory mode)
- getUserId: (lobbyId: string, playerId: string) => number | undefined

**State:**
- sessionStats: Map<string, Map<string, SessionSummary>> (lobbyId -> playerId -> summary)
- votingSpeedAccumulator: Map<string, Map<string, { totalMs: number, count: number }>> (for running average)

**Constructor:** Subscribe to events via eventBus.on():
- 'estimation:vote_cast' -> handleVoteCast (increment totalVotes, track voting speed)
- 'estimation:full_consensus_reached' -> handleConsensus (increment consensusCount for all voters)
- 'combat:boss_damaged' -> handleBossDamage (increment totalDamageDealt)
- 'combat:boss_defeated' -> handleBossDefeated (increment bossesDefeated)
- 'combat:player_revived' -> handleRevival (increment revives for reviver)
- 'combat:player_permanently_downed' -> handleDeath (increment deaths)
- 'session:phase_changed' -> handlePhaseChange (emit session_complete at game_over or victory)
- 'session:lobby_destroyed' -> handleLobbyDestroyed (cleanup)

**Event handlers:**

handleVoteCast(payload: { lobbyId, playerId, votingStartedAt? }):
- Get or create session summary for player
- Increment totalVotes
- If votingStartedAt exists in the payload, calculate speed = Date.now() - votingStartedAt, accumulate in votingSpeedAccumulator, update averageVotingSpeedMs
- Fire-and-forget: persistStat(lobbyId, playerId, 'totalVotes', 1)

handleConsensus(payload: { lobbyId, voters: string[] }):
- For each voter: increment consensusCount in session summary
- Fire-and-forget: update consensusRate for each voter. ConsensusRate = (lifetime consensusCount / lifetime totalVotes) * 100. Since we don't have lifetime totals locally, just increment a counter and let the profile page compute the rate. Actually simpler: persist the consensus vote count with incrementUserStat. The rate can be computed on read from totalVotes and consensus count.
- NOTE: The schema has consensusRate as a computed field. For simplicity, persist a separate consensus vote count. Actually the existing accuracyScore field in userStats serves this purpose. Use incrementUserStat for 'ticketsEstimated' as proxy. Let's keep it simple: track in session, persist consensusRate as a rolling update. On each consensus event, increment a counter. On session end, calculate rate and updateUserStats.

SIMPLIFICATION: For lifetime persistence, use these existing columns:
- totalVotes -> new column
- totalDamageDealt -> existing column
- bossesDefeated -> existing column
- revivesPerformed -> existing column
- totalDeaths -> new column
- consensusRate -> new column (update as rolling percentage on session end)
- averageVotingSpeedMs -> new column (update as rolling average on session end)

So: event handlers increment in-memory session counters fire-and-forget for individual stats (totalVotes, totalDamageDealt, bossesDefeated, revivesPerformed, totalDeaths). For consensusRate and averageVotingSpeedMs, compute and persist at session end (handlePhaseChange for game_over/victory).

handleBossDamage(payload: { lobbyId, playerId, damage }):
- Increment totalDamageDealt by damage amount in session summary
- Fire-and-forget: storage.incrementUserStat(userId, 'totalDamageDealt', damage)

handleBossDefeated(payload: { lobbyId }):
- For all players in session summary for this lobby: increment bossesDefeated
- Fire-and-forget: storage.incrementUserStat(userId, 'bossesDefeated', 1) for each player

handleRevival(payload: { lobbyId, playerId (reviver), targetId }):
- Increment revives for the reviver in session summary
- Fire-and-forget: storage.incrementUserStat(userId, 'revivesPerformed', 1)

handleDeath(payload: { lobbyId, playerId }):
- Increment deaths in session summary
- Fire-and-forget: storage.incrementUserStat(userId, 'totalDeaths', 1)

handlePhaseChange(payload: { lobbyId, newPhase }):
- If newPhase is 'game_over' or 'victory':
  - For each player in session summaries: compute final consensusRate = (consensusCount / totalVotes) * 100, compute averageVotingSpeedMs
  - Fire-and-forget: storage.updateUserStats(userId, { consensusRate, averageVotingSpeedMs }) for computed fields
  - Emit 'stats:session_complete' with all player summaries for this lobby

handleLobbyDestroyed(payload: { lobbyId }):
- Delete sessionStats and votingSpeedAccumulator for lobby

**Public API:**
- getSessionSummary(lobbyId, playerId): SessionSummary | null
- getAllSessionSummaries(lobbyId): Record<string, SessionSummary>
- cleanupLobby(lobbyId): void

**Private persistStat(lobbyId, playerId, stat, increment):**
Follow ProgressionManager pattern exactly:
- Get userId via deps.getUserId(lobbyId, playerId)
- If no userId or no storage, return
- await storage.incrementUserStat(userId, stat, increment)
- Wrap in try/catch, log error on failure
