<task type="auto">
  <name>Task 1: Configure CodeQL Merge Blocking via Ruleset</name>
  <files>.github/rulesets/main-protection.json (documentation only - created via API)</files>
  <action>
Create a GitHub ruleset via `gh api` to block PRs based on CodeQL severity:

1. Use `gh api` to create a repository ruleset with code_scanning rule:
   - name: "security-gates"
   - target: branch
   - enforcement: active
   - conditions: refs/heads/main
   - rules: code_scanning with security_alerts_threshold: "high_or_higher"

2. The ruleset should NOT use alerts_threshold (we only care about security alerts, not quality)

Command structure:
```bash
gh api repos/{owner}/{repo}/rulesets --method POST \
  --field name="security-gates" \
  --field target="branch" \
  --field enforcement="active" \
  --field "conditions[ref_name][include][]=refs/heads/main" \
  --field "rules[][type]=code_scanning" \
  --field "rules[0][parameters][code_scanning_tools][0][tool]=CodeQL" \
  --field "rules[0][parameters][code_scanning_tools][0][security_alerts_threshold]=high_or_higher" \
  --field "rules[0][parameters][code_scanning_tools][0][alerts_threshold]=none"
```

If the API call fails due to format, use the JSON body approach:
```bash
gh api repos/{owner}/{repo}/rulesets --method POST --input - <<EOF
{
  "name": "security-gates",
  "target": "branch",
  "enforcement": "active",
  "conditions": {
    "ref_name": {
      "include": ["refs/heads/main"]
    }
  },
  "rules": [{
    "type": "code_scanning",
    "parameters": {
      "code_scanning_tools": [{
        "tool": "CodeQL",
        "security_alerts_threshold": "high_or_higher",
        "alerts_threshold": "none"
      }]
    }
  }]
}
EOF
```

Note: This integrates with existing CodeQL workflow in .github/workflows/codeql.yml (no changes needed there).

**Step 1: Create .gitleaks.toml configuration**

Create gitleaks config at repo root with:
- Extend default rules (useDefault = true)
- Allowlist paths: node_modules, .git, package-lock.json, markdown files, test files
- Allowlist regexes: example, sample, placeholder, TODO, CHANGEME patterns

**Step 2: Update .husky/pre-commit**

Existing hook runs `npm test`. Update to also run gitleaks:

```bash
#!/usr/bin/env sh
. "$(dirname -- "$0")/_/husky.sh"

echo "Running gitleaks secret detection..."
if command -v gitleaks >/dev/null 2>&1; then
  gitleaks protect --staged --verbose --redact
else
  echo "Warning: gitleaks not installed. Install from https://github.com/gitleaks/gitleaks"
  echo "Skipping local secret detection (CI will still catch secrets)"
fi

npm test
```

Note: Pre-commit should NOT block if gitleaks isn't installed locally (CI is the safety net).
The warning educates developers to install it for faster feedback.

**Step 3: Create .github/workflows/security-scan.yml**

Create new workflow for gitleaks CI scanning:
- Trigger: push to main, PRs to main
- Uses gitleaks/gitleaks-action@v2
- References .gitleaks.toml config via GITLEAKS_CONFIG env var
- GITHUB_TOKEN for PR annotations

This workflow is separate from ci.yml to keep concerns isolated and allow different concurrency settings.
