## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> /api/auth/providers | Browser fetches a public boolean flag — no auth required, no PII in request or response |
| client render gate | Render decision based on a server-supplied boolean; a hostile server response cannot escalate privileges (worst case: button shown when login impossible -> back to current loop, no security regression) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-43-01 | Tampering | `/api/auth/providers` response | accept | Endpoint already returns a static boolean derived from `process.env`; no user input flows in. Worst-case tamper (MITM forces `auth0:true`) puts the user back to the pre-fix state — no privilege escalation. |
| T-43-02 | Information Disclosure | `providersConfigured` in client store | accept | The boolean is intentionally public (already exposed via `/providers`). Persisted Zustand state via `partialize` — verify the new field is NOT persisted (it's a session fetch result). |
| T-43-03 | Denial of Service | repeated `/providers` polling | mitigate | `fetchProviders` is called once inside `checkAuth` (which runs once on app mount). No render-time fetch, no polling. |
</threat_model>
