Build `client/src/components/ui/MusicControls.tsx` — the unified control panel (D-01) replacing BossMusicControls. Host gets URL input + play/stop + history dropdown; non-host gets a read-only status indicator (D-02, MUSIC-05). SCOPE NOTE (team-lead override — Option B, accept-only playlists): The `youtube_play` payload is the EXISTING `{ videoId: string; url: string }`. Do NOT add a `playlistId` field, do NOT touch the socket types or Zod schema. Behavior on submit:
- `watch?v=...` or `watch?v=...&list=...` → `extractVideoId` returns the 11-char id → emit `{ videoId, url }` (first video plays; this already works today).
- bare `playlist?list=...` → `extractVideoId` returns null → show a user-facing note "This playlist URL may not play inline — try a direct video URL instead" but STILL save to history (title resolves via oEmbed) and STILL emit `{ videoId: '', url }` so the attempt is made. (Server-side Zod requires `videoId.min(1)`, so a bare playlist emit is rejected server-side and produces a game_error toast — that is the acceptable accept-only outcome; the note sets host expectations.)
</objective>
