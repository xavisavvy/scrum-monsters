**client/index.html** — Fix the viewport meta tag:
- Remove `maximum-scale=1` (violates WCAG 1.4.4 — prevents pinch-to-zoom)
- Add `viewport-fit=cover` (enables edge-to-edge rendering so env() safe-area values work)
- Result: `content="width=device-width, initial-scale=1.0, viewport-fit=cover"`

**client/src/styles/mobile.css** — Create new mobile foundation stylesheet with:

1. Safe-area utility classes (in `@layer utilities`):
   - `.pb-safe` → `padding-bottom: env(safe-area-inset-bottom);`
   - `.pt-safe` → `padding-top: env(safe-area-inset-top);`
   - `.pl-safe` → `padding-left: env(safe-area-inset-left);`
   - `.pr-safe` → `padding-right: env(safe-area-inset-right);`
   - `.p-safe` → all four insets
   - `.pb-safe-plus` → `padding-bottom: calc(16px + env(safe-area-inset-bottom));` (for HUD elements)

2. Touch-action fix (in `@layer base`):
   - Add `touch-action: manipulation;` to all interactive elements (`button, a, input, select, textarea, [role="button"]`) — prevents double-tap zoom without blocking pinch-to-zoom
   - This replaces the old `maximum-scale=1` approach

3. Dynamic viewport height fix:
   - Add `min-height: 100dvh;` to body with `100vh` fallback: `min-height: 100vh; min-height: 100dvh;`
   - This fixes the iOS Safari address bar height issue

**client/src/index.css** — Update the global `canvas` rule:
- Change `touch-action: none;` to be scoped. Add a comment: `/* touch-action: none applied to interactive Three.js canvases via component className, not globally */`
- Remove the global `touch-action: none` from the `canvas` selector (it blocks scrolling on non-interactive canvases)
- Keep `width: 100% !important; height: 100% !important;` on canvas

**client/src/App.tsx** — Add import for mobile.css:
- Add `import './styles/mobile.css';` after the existing `import './styles/tokens.css';` line (or after retro.css import — follow the existing pattern for style imports)

**client/src/components/ui/GameButton.tsx** — Update size variants in the CVA definition to enforce 44px minimum height:

```typescript
size: {
  sm: 'px-3 py-2 min-h-[44px] min-w-[44px] text-xs',    // was: px-3 py-1 (24-28px tall)
  md: 'px-6 py-3 min-h-[44px] text-sm',                   // already sufficient but explicit
  lg: 'px-8 py-4 min-h-[44px] text-base',                 // already sufficient but explicit
}
```

Key changes:
- `sm`: `py-1` -> `py-2`, add `min-h-[44px] min-w-[44px]` (the sm variant is used for compact mobile buttons and must meet touch target requirements)
- `md` and `lg`: Add `min-h-[44px]` explicitly to prevent future regressions

**client/src/styles/retro.css** — Update `.retro-button` and `.fibonacci-button`:

1. `.retro-button` class: Add `min-height: 44px;` to the base rule. The existing `padding: 12px 24px` gives ~40px with Press Start 2P — the explicit min-height closes the gap.

2. `.fibonacci-button` class: Add `min-height: 44px;` and `min-width: 44px;` to ensure touch target compliance even when the grid compresses on narrow screens.

3. `.fibonacci-grid`: Change to mobile-responsive grid:
   ```css
   .fibonacci-grid {
     display: grid;
     grid-template-columns: repeat(auto-fit, minmax(60px, 1fr));
     gap: 8px;
     margin: 16px 0;
   }

   @media (max-width: 767px) {
     .fibonacci-grid {
       grid-template-columns: repeat(4, 1fr);
       gap: 6px;
     }
   }
   ```
   On mobile (<768px), use a fixed 4-column grid. With 12 Fibonacci options (including ?), this creates 3 rows of 4 — each button is ~84px wide on a 375px screen (with gaps), well above 44px. The auto-fit on desktop remains unchanged.

Do NOT change the `.fibonacci-button` aspect-ratio — keep `aspect-ratio: 1` on desktop. On mobile, override to remove it so buttons can be rectangular (wider than tall) for better text readability:
```css
@media (max-width: 767px) {
  .fibonacci-button {
    aspect-ratio: auto;
  }
}
```
