  <action>
Create `client/src/components/game/MobileControls.tsx` — a virtual gamepad overlay for touch devices:

**Props interface:**
```typescript
interface MobileControlsProps {
  onKeyDown: (code: string) => void;  // Same signature as keyboard handler
  onKeyUp: (code: string) => void;
  isActive: boolean;  // Whether battle is active (controls only show during active battle)
}
```

**Component structure:**
- Fixed position overlay at bottom of screen, z-index 40 (below UI panels at z-50, but above game world)
- `pointer-events-none` on the container, `pointer-events-auto` on individual buttons
- Uses `onPointerDown` and `onPointerUp` exclusively (no onClick, no onTouchStart)
- Apply `touch-action: none` on each button to prevent browser gesture interference

**Left side — D-pad (movement):**
- 4 directional buttons arranged in a cross/plus pattern
- Up button: calls `onKeyDown('ArrowUp')` on pointerdown, `onKeyUp('ArrowUp')` on pointerup
- Down: `ArrowDown`
- Left: `ArrowLeft`
- Right: `ArrowRight`
- Each button: `min-w-[48px] min-h-[48px]` (slightly larger than 44px for D-pad ergonomics)
- Use arrow characters (▲ ▼ ◄ ►) or simple text labels
- Position: bottom-left, with safe-area-bottom padding (use `pb-safe` class from Plan 01 or inline `env(safe-area-inset-bottom)`)

**Right side — Action buttons:**
- SHOOT button: calls `onKeyDown('ControlLeft')` on pointerdown, `onKeyUp('ControlLeft')` on pointerup (maps to Ctrl key used for shooting)
- JUMP button: calls `onKeyDown('Space')` on pointerdown, `onKeyUp('Space')` on pointerup
- SPECIAL button: calls `onKeyDown('KeyQ')` on pointerdown, `onKeyUp('KeyQ')` on pointerup (maps to Q for special attack)
- Each button: `min-w-[56px] min-h-[56px]` (action buttons slightly larger for thumb targeting)
- Position: bottom-right, with safe-area-bottom padding

**Styling:**
- Semi-transparent background on buttons: `bg-black/40 border-2 border-white/30 rounded-lg`
- Text in white, `font-jrpg text-[10px]` for labels
- Active state: `bg-white/20` on pointer down (use CSS :active or React state)
- The overlay should not interfere with the game world behind it

**Return null if `!isActive`.**

**Important implementation detail for onPointerUp:** Add `onPointerCancel` alongside `onPointerUp` to handle cases where the finger slides off the button — both should call the keyUp handler to prevent "stuck" keys.

Also add `onContextMenu={(e) => e.preventDefault()}` to the container to prevent long-press context menus on mobile.

Modify `client/src/components/game/PlayerController.tsx`:

1. **Add imports:**
   ```typescript
   import { MobileControls } from './MobileControls';
   import { useIsMobile } from '@/hooks/use-is-mobile';
   ```

2. **Add mobile detection** inside the `PlayerController` component:
   ```typescript
   const isMobile = useIsMobile();
   ```

3. **Convert screen click from onClick to onPointerDown:**

   Find the `handleScreenClick` function (it handles shooting when clicking on the game area). Replace:
   - The function signature: change `React.MouseEvent<HTMLDivElement>` to `React.PointerEvent<HTMLDivElement>`
   - Rename to `handleScreenPointerDown` for clarity
   - Add at the top of the handler: `if (event.pointerType === 'touch') { event.preventDefault(); }` to prevent synthetic mouse events
   - Keep ALL existing shooting logic unchanged

   Then update the JSX where this handler is attached:
   - Change `onClick={isActive ? handleScreenClick : undefined}` to `onPointerDown={isActive ? handleScreenPointerDown : undefined}`

4. **Convert onMouseDown to onPointerDown:**

   Find the `onMouseDown` handler on the same div (used for focus). Change:
   - `onMouseDown={isActive ? (e) => { e.currentTarget.focus(); } : undefined}`
   - To: `onPointerDown` is already being used for shooting above. The focus behavior should be part of `handleScreenPointerDown` — add `(event.currentTarget as HTMLElement).focus?.()` at the start of the handler (before the shooting logic).

   Actually, if both handlers are on the same div, combine them: the pointerdown handler should first focus the element, then handle shooting. Remove the separate onMouseDown handler.

5. **Create callback handlers for MobileControls:**
   ```typescript
   const handleMobileKeyDown = useCallback((code: string) => {
     setKeys(prev => new Set(prev).add(code));

     // Handle jump (same logic as keyboard Space handler)
     if (code === 'Space' && !isJumping) {
       setIsJumping(true);
       emit('player_jump', { isJumping: true });
       setTimeout(() => {
         setIsJumping(false);
         emit('player_jump', { isJumping: false });
       }, jumpDuration);
     }

     // Handle special attack (same logic as keyboard Q handler)
     if (code === 'KeyQ') {
       setQPressed(true);
     }

     // Handle shoot (same logic as keyboard Ctrl handler)
     if (code === 'ControlLeft') {
       setCtrlPressed(true);
     }
   }, [isJumping, emit, jumpDuration]);

   const handleMobileKeyUp = useCallback((code: string) => {
     setKeys(prev => {
       const next = new Set(prev);
       next.delete(code);
       return next;
     });

     if (code === 'KeyQ') {
       setQPressed(false);
     }
     if (code === 'ControlLeft') {
       setCtrlPressed(false);
     }
   }, []);
   ```

   NOTE: Look at the existing `handleKeyDown` and `handleKeyUp` functions to understand the exact key handling logic for jump/shoot/special. The mobile handlers must replicate the same side effects (setIsJumping, emit, setTimeout, setCtrlPressed, setQPressed). Do NOT call the keyboard handler directly — the keyboard handler takes a KeyboardEvent, not a string code.

6. **Render MobileControls conditionally:**
   Add MobileControls at the end of the PlayerController JSX return, as a sibling to the existing game area div:
   ```tsx
   {isMobile && (
     <MobileControls
       onKeyDown={handleMobileKeyDown}
       onKeyUp={handleMobileKeyUp}
       isActive={isActive}
     />
   )}
   ```

   Where `isActive` is the existing variable that determines if battle controls should respond to input (check the existing code for how this is determined — it's likely based on the game phase or combat state).
