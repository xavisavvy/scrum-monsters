<objective>
Fix the client-side root causes of the Phase 41 reconnection bug:
1. The three session-storage keys drift apart because they are written in different code paths and never validated against each other.
2. `lastLobbySnapshot` is initialized to `null` on every cold load even when `LOBBY_SNAPSHOT_KEY` exists in localStorage (write-only key).
3. `reconnectToLobby()` blindly emits whatever token is in storage without checking that the token's lobbyId matches the route's lobbyId.
4. Several `reconnect_response` failure paths clear in-memory state but leave localStorage entries behind, producing drift.
5. GamePage's socket-listener `useEffect` re-registers all listeners whenever `currentLobby` or `lastGamePhase` changes, losing events that arrive during the gap (the snapshot-vs-last-lobby drift origin).

Strategy: introduce a single `sessionStorage.ts` helper that owns the three keys atomically, wire `useWebSocket` to read it on mount and validate before emitting, symmetrize the failure-path cleanup, and stabilize the GamePage listener `useEffect` so handlers read fresh state via refs.

Out of scope (deferred, per user decision): multi-tab races, storage-event cross-tab sync, leader-tab mutex.

Purpose: Eliminates the wrong-lobby reconnect attempt and the snapshot/last-lobby drift entirely, which is the upstream cause of the duplicate-self symptom even before any server-side changes.

Output: A coherent client session layer; new unit tests prove drift detection and lobbyId-mismatch handling.
</objective>
