  <files>docker/postgres-backup/restore-from-s3.sh</files>
  <action>
Create `docker/postgres-backup/restore-from-s3.sh` based on the research code example. The script must:

1. Accept one argument: the S3 key (e.g., `scrummonsters/scrummonsters_2026-03-09T02:00:00.sql.gz`)
2. Source `/opt/scrummonsters/.env` for `BACKUP_S3_BUCKET`, `POSTGRES_USER`, `POSTGRES_DB`, and AWS credentials
3. Download the backup from S3 using `aws s3 cp` to `/tmp/restore.sql.gz`
4. Stop the app container: `docker compose -f docker-compose.prod.yml stop app`
5. Drop and recreate the database (connect to `postgres` db, not the target db):
   - `DROP DATABASE IF EXISTS ${POSTGRES_DB};`
   - `CREATE DATABASE ${POSTGRES_DB} OWNER ${POSTGRES_USER};`
6. Restore using `gunzip -c /tmp/restore.sql.gz | docker compose -f docker-compose.prod.yml exec -T postgres psql -U ${POSTGRES_USER} -d ${POSTGRES_DB}`
   - CRITICAL: Use `gunzip | psql`, NOT `pg_restore`. The backup format is plain-text SQL (confirmed in backup.sh -- no `-Fc` flag).
7. Verify data integrity:
   - Count public tables via `information_schema.tables`
   - Count rows in `users` table (may be 0 if no users yet, that is fine)
8. Restart the app: `docker compose -f docker-compose.prod.yml start app`
9. Wait 10s, then curl `https://scrummonsters.com/api/health`
10. Clean up `/tmp/restore.sql.gz`

Use `set -e` for fail-fast. Print numbered step progress (`[1/6]`, `[2/6]`, etc.). Use `COMPOSE="docker compose -f docker-compose.prod.yml"` variable to avoid repetition.

Make the script executable: `chmod +x docker/postgres-backup/restore-from-s3.sh`
  </action>
  <verify>

`ls -la docker/postgres-backup/restore-from-s3.sh` shows executable permission.
  </verify>
