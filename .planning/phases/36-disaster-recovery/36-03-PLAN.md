**9.1 Restart Procedures**

**9.4 Common Failure Scenarios**

For each scenario, document: **Symptoms**, **Diagnosis**, **Fix**, **Verify**.

**Scenario 1: OOM Kill**
- Symptoms: Container stops unexpectedly, app unresponsive, health check failing
- Diagnosis: `dmesg | grep -i oom`, `docker inspect <container> | grep OOMKilled`, `docker stats --no-stream`
- Fix: Identify which container was killed. If app: restart it. If systemic: review memory limits, consider reducing Prometheus retention or Grafana memory limit. `docker compose -f docker-compose.prod.yml up -d <killed-service>`
- Verify: `docker stats --no-stream` shows all containers running, total under 900 MB

**Scenario 2: Disk Full**
- Symptoms: Database write errors, backup failures, container creation fails
- Diagnosis: `df -h`, `docker system df`, `du -sh /var/lib/docker/`
- Fix: Prune unused Docker resources: `docker system prune -f`, `docker image prune -a -f` (removes all unused images). Check for old backup files: `ls -lah /tmp/restore*`. Consider pruning old Prometheus data if needed.
- Verify: `df -h` shows >20% free on root partition

**Scenario 3: Database Connection Exhaustion**
- Symptoms: App logs show "too many connections", new WebSocket connections fail, existing games still work
- Diagnosis: `docker compose -f docker-compose.prod.yml exec postgres psql -U scrummonsters -d scrummonsters -c "SELECT count(*) FROM pg_stat_activity;"` and `SELECT state, count(*) FROM pg_stat_activity GROUP BY state;`
- Fix: Restart app to release connections: `docker compose -f docker-compose.prod.yml restart app`. If persistent, check for connection leaks in app code.
- Verify: Connection count drops after restart, new connections work

**Scenario 4: TLS Certificate Expiry**
- Symptoms: Browser shows security warning, HTTPS connections fail, Prometheus TLSCertExpiringSoon alert fires
- Diagnosis: `echo | openssl s_client -connect scrummonsters.com:443 -servername scrummonsters.com 2>/dev/null | openssl x509 -noout -dates`
- Fix:
  1. Verify port 80 is open in Lightsail firewall (required for HTTP-01 challenge)
  2. Check NPM logs: `docker compose -f docker-compose.prod.yml logs nginx-proxy-manager | grep -i "renew\|certbot\|certificate"`
  3. If NPM renewal failed: access NPM admin via SSH tunnel (`ssh -L 81:localhost:81 ubuntu@34.199.135.244`), go to SSL Certificates, delete the cert, and re-request it
  4. Do NOT close port 80 -- Let's Encrypt HTTP-01 requires it permanently
- Verify: `openssl s_client` shows new notAfter date, browser loads without warnings

**Scenario 5: App Crash Loop**
- Symptoms: Health check fails repeatedly, container restarts every 30s, `docker ps` shows container restarting
- Diagnosis: `docker compose -f docker-compose.prod.yml logs --tail=100 app`, check for startup errors (DB connection, missing env vars, uncaught exceptions)
- Fix:
  1. Check recent deploy: if new code deployed, rollback (see 9.3)
  2. Check database: `docker compose -f docker-compose.prod.yml exec postgres pg_isready` -- if DB is down, restart postgres first
  3. Check env vars: `docker compose -f docker-compose.prod.yml config` to verify .env loaded correctly
- Verify: `curl https://scrummonsters.com/api/health` returns 200, `docker ps` shows app running (not restarting)
