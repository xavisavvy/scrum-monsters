    **deploy.sh** — Create at repo root, mark executable with `chmod +x deploy.sh`:

    Script performs a one-command deploy from the local machine. Uses SSH to execute commands on the VPS.

    Variables at the top:
    ```bash
    REMOTE_USER="ubuntu"
    REMOTE_HOST=""          # Filled in during initial setup (Lightsail static IP)
    SSH_KEY="$HOME/.ssh/lightsail_scrummonsters"
    REMOTE_DIR="/opt/scrummonsters"
    ```

    The script should:
    1. Print "Deploying ScrumMonsters to scrummonsters.com..."
    2. SSH in using the key and execute a heredoc with `set -e`:
       - Step 1/4: `cd $REMOTE_DIR && git pull origin main`
       - Step 2/4: `docker compose -f docker-compose.prod.yml build app`
       - Step 3/4: `docker compose -f docker-compose.prod.yml run --rm app npm run db:push` (runs drizzle-kit push against the live postgres container)
       - Step 4/4: `docker compose -f docker-compose.prod.yml up -d --no-deps app` (restarts only the app container, keeps postgres and NPM running)
    3. Print "Deploy complete. Check https://scrummonsters.com"

    Add a usage comment at the top:
    ```bash
    #!/bin/bash
    # deploy.sh - One-command deploy for ScrumMonsters
    # Prerequisites:
    #   - SSH key at ~/.ssh/lightsail_scrummonsters (set REMOTE_HOST below after provisioning)
    #   - VPS already provisioned per runbook.md Initial Setup section
    # Usage: ./deploy.sh
    set -e
    ```

    **runbook.md** — Create at repo root. This is the human operations guide. Structure:

    ```markdown
    # ScrumMonsters Operations Runbook

    Covers: initial VPS setup, deploy procedure, and what deploy.sh does step by step.

    ## Quick Reference

    | Task | Command |
    |------|---------|
    | Deploy latest code | `./deploy.sh` |
    | SSH to VPS | `ssh -i ~/.ssh/lightsail_scrummonsters ubuntu@<static-ip>` |
    | View app logs | `ssh in → docker compose -f docker-compose.prod.yml logs -f app` |
    | Restart stack | `ssh in → cd /opt/scrummonsters && sudo systemctl restart scrummonsters` |
    | NPM admin UI | SSH tunnel: `ssh -L 81:localhost:81 ubuntu@<ip>` then visit http://localhost:81 |

    ## Part 1: Initial VPS Setup (one-time)

    Steps: generate SSH key, create Lightsail Micro instance in us-east-1, attach static IP, configure Lightsail firewall (ports 22/80/443 only — NOT 81 yet), SSH in, install Docker via official apt repo, add ubuntu to docker group, create /opt/scrummonsters, clone repo, create .env from template, create systemd unit.

    Include the full systemd unit content as a copy-paste block:
    ```ini
    # /etc/systemd/system/scrummonsters.service
    [Unit]
    Description=ScrumMonsters Docker Compose Application
    Requires=docker.service
    After=docker.service network-online.target
    Wants=network-online.target

    [Service]
    Type=oneshot
    RemainAfterExit=yes
    WorkingDirectory=/opt/scrummonsters
    ExecStart=/usr/bin/docker compose -f docker-compose.prod.yml --env-file .env up -d
    ExecStop=/usr/bin/docker compose -f docker-compose.prod.yml down
    StandardOutput=journal
    StandardError=journal

    [Install]
    WantedBy=multi-user.target
    ```

    Then: `sudo systemctl daemon-reload && sudo systemctl enable scrummonsters && sudo systemctl start scrummonsters`

    Include the .env file template with all required and optional vars, with instructions to run `openssl rand -base64 32` for secrets. Mark the file as needing `chmod 600 .env`.

    Also include: run initial db:push (`docker compose -f docker-compose.prod.yml run --rm app npm run db:push`), then verify the app is reachable at http://<static-ip>:5000/api/health before proceeding to DNS/TLS setup.

    ## Part 2: DNS and TLS Setup (one-time)

    Steps: create Lightsail static IP (if not done), attach to instance, create Route 53 A record at apex pointing to static IP, temporarily open port 81 in Lightsail firewall, access NPM at http://<ip>:81, change default credentials, create proxy host for scrummonsters.com → app:5000 with WebSocket Support enabled, request Let's Encrypt cert on SSL tab with Force SSL enabled, verify HTTPS works, then remove port 81 from Lightsail firewall.

    Include the warning: "Do not close port 80 — Let's Encrypt HTTP-01 renewal requires it to remain open."

    ## Part 3: What deploy.sh Does (Step by Step)

    Explain each of the 4 steps in plain language — what git pull does, why we build only the app container, what db:push does and why it's safe to run repeatedly (idempotent on Drizzle push), why we use --no-deps (keeps postgres and NPM running during app restart).

    ## Part 4: OAuth Setup (one-time)

    After the domain is live with HTTPS, update OAuth app redirect URIs:
    - Google Cloud Console → APIs & Services → Credentials → OAuth 2.0 Client → Authorized redirect URIs: add `https://scrummonsters.com/api/auth/google/callback`
    - GitHub → Settings → Developer Settings → OAuth Apps → Authorization callback URL: `https://scrummonsters.com/api/auth/github/callback`
    ```

    Use real Markdown with headers, code blocks, and tables. Keep it practical — this is an operations document the user will read during the actual deployment.
