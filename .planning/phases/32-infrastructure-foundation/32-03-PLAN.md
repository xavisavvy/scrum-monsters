<task type="checkpoint:human-action" gate="blocking">
  <what-to-do>
    Provision the Lightsail VPS and configure firewall. Follow the "Part 1: Initial VPS Setup" section of runbook.md.

    Specific steps for this checkpoint:

    1. Generate SSH key pair on your local machine:
       `ssh-keygen -t ed25519 -C "lightsail-scrummonsters" -f ~/.ssh/lightsail_scrummonsters`

    2. In the AWS Console (us-east-1 region):
       - Create a Lightsail instance: OS Only → Ubuntu 22.04 LTS → $5/mo plan (Micro)
       - Under "Add your SSH key" during creation, upload the public key from `~/.ssh/lightsail_scrummonsters.pub`
       - Name the instance: scrummonsters-prod

    3. After instance starts:
       - Create a static IP and attach it to scrummonsters-prod
       - Note the static IP address

    4. Configure the Lightsail firewall (Instance → Networking → IPv4 Firewall):
       - Keep TCP 22 (SSH)
       - Add TCP 80 (HTTP — required for Let's Encrypt challenge)
       - Add TCP 443 (HTTPS)
       - Add TCP 81 (NPM admin — needed for TLS setup only, will be removed later)
       - Remove any other default rules

    5. SSH into the instance to verify access:
       `ssh -i ~/.ssh/lightsail_scrummonsters ubuntu@<static-ip>`

    6. Once SSHed in, install Docker (copy commands from runbook.md "Install Docker" section):
       - Run the apt repo setup commands
       - Install docker-ce, docker-ce-cli, containerd.io, docker-buildx-plugin, docker-compose-plugin
       - Add ubuntu to the docker group: `sudo usermod -aG docker ubuntu`
       - `newgrp docker` to apply immediately
       - Verify: `docker --version` and `docker compose version`

    7. Clone the repo and create the .env file:
       ```bash
       sudo mkdir -p /opt/scrummonsters
       sudo chown ubuntu:ubuntu /opt/scrummonsters
       cd /opt/scrummonsters
       git clone https://github.com/<your-repo>/ScrumMonsters.git .
       ```
       Create `.env` from the template in runbook.md. Generate secrets:
       - `POSTGRES_PASSWORD=$(openssl rand -base64 32)`
       - `SESSION_SECRET=$(openssl rand -base64 48)`
       Set `NODE_ENV=production`, `PORT=5000`, `ALLOWED_ORIGINS=https://scrummonsters.com`, `OAUTH_CALLBACK_BASE_URL=https://scrummonsters.com`
       Then: `chmod 600 .env`

    8. Create the systemd unit:
       `sudo nano /etc/systemd/system/scrummonsters.service`
       Paste the unit from runbook.md Part 1.
       `sudo systemctl daemon-reload && sudo systemctl enable scrummonsters`

    9. Start the stack for the first time:
       `docker compose -f docker-compose.prod.yml --env-file .env up -d`
       Wait 2-3 minutes for the build to complete (it runs npm run build inside the Docker build).

    10. Run initial database schema setup:
        `docker compose -f docker-compose.prod.yml run --rm app npm run db:push`

    11. Verify the app is running:
        `curl http://localhost:5000/api/health`
        Expect: `{"status":"ok"}` or similar healthy response.

    Also update deploy.sh: fill in `REMOTE_HOST="<static-ip>"` with the actual IP.
  </what-to-do>
  <resume-signal>Type "vps-ready" once: the instance is running, Docker is installed, the stack is up, db:push succeeded, and `curl http://localhost:5000/api/health` returns healthy. Include the static IP in your response.</resume-signal>
</task>

<task type="checkpoint:human-action" gate="blocking">
  <what-to-do>
    Point scrummonsters.com to the Lightsail static IP via Route 53 and get HTTPS working via Nginx Proxy Manager.

    **Step 1 — Route 53 DNS:**
    1. AWS Console → Route 53 → Hosted zones → scrummonsters.com
    2. Create record:
       - Record name: (leave blank — this sets the apex/root domain)
       - Record type: A
       - Value: `<static-ip>` (the Lightsail static IP from the previous checkpoint)
       - TTL: 300
       - Routing policy: Simple
    3. Save the record. DNS usually propagates within a few minutes for Route 53.
    4. Verify DNS propagation: `nslookup scrummonsters.com 8.8.8.8` should return the static IP.

    **Step 2 — Nginx Proxy Manager TLS setup:**
    1. Open `http://<static-ip>:81` in a browser (port 81 is temporarily open in the firewall)
    2. Log in with default credentials: `admin@example.com` / `changeme`
    3. Immediately change both the email and password when prompted
    4. Go to Proxy Hosts → Add Proxy Host:
       - Domain Names: `scrummonsters.com`
       - Scheme: `http`
       - Forward Hostname/IP: `app` (the Docker Compose service name)
       - Forward Port: `5000`
       - Enable "Block Common Exploits"
       - Enable "Websocket Support" (critical for Socket.IO)
    5. On the SSL tab:
       - SSL Certificate: Request a new SSL Certificate
       - Select "Let's Encrypt"
       - Enable "Force SSL"
       - Enable "HTTP/2 Support"
       - Agree to Let's Encrypt ToS
       - Click Save — NPM will request the cert via HTTP-01 challenge (port 80 must be open)

    **Step 3 — Verify HTTPS:**
    1. Visit `https://scrummonsters.com` in a browser
    2. Confirm: browser shows padlock (no security warnings)
    3. Confirm: ScrumMonsters lobby loads (same experience as Replit)
    4. Open browser DevTools → Network → Filter by "WS" — confirm WebSocket connection upgrades (101 Switching Protocols)

    **Step 4 — Remove port 81 from Lightsail firewall:**
    Now that TLS is set up, remove port 81 from the Lightsail firewall (AWS Console → Lightsail → scrummonsters-prod → Networking → IPv4 Firewall → delete TCP 81 rule).
    NPM admin is now only accessible via SSH tunnel: `ssh -L 81:localhost:81 ubuntu@<static-ip>`

    **Step 5 — Test VPS reboot auto-restart:**
    SSH in and run: `sudo reboot`
    Wait 2-3 minutes, then visit https://scrummonsters.com — the app should be back up without manual intervention.
  </what-to-do>
  <resume-signal>Type "live" once: https://scrummonsters.com loads the lobby over HTTPS, WebSocket connects, port 81 is removed from the firewall, and the app survived a VPS reboot. Describe any issues encountered.</resume-signal>
</task>
