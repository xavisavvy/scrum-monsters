Create `client/src/components/ui/StatBar.tsx` — a generic progress bar component that can display any numeric stat.

Props interface:
```typescript
interface StatBarProps {
  value: number;              // Current value (0-100 if no max, or raw value if max provided)
  max?: number;               // Maximum value (default 100)
  variant?: 'health' | 'xp' | 'mana' | 'timer';  // Controls fill color
  label?: string;             // ARIA label text
  showValue?: boolean;        // Show "value/max" text overlay
  size?: 'sm' | 'md' | 'lg'; // Track height: sm=12px, md=20px, lg=28px
  className?: string;         // Additional classes on outer container
}
```

Implementation:
1. Calculate percentage: `const pct = Math.max(0, Math.min(100, (value / (max ?? 100)) * 100))`
2. Map variant to fill color using --jrpg-* tokens:
   - `health`: `var(--jrpg-health-high)` (dynamic color handled by HealthBar, StatBar uses static green)
   - `xp`: `var(--jrpg-xp-fill)` — blue
   - `mana`: `var(--jrpg-mana-fill)` — purple
   - `timer`: amber-400
3. Track uses `bg-jrpg-panel` background with `border` from tokens
4. Fill uses `transition: width 0.5s ease-out` (CSS transition, not JS animation — simpler and sufficient)
5. Size maps: sm → `h-3`, md → `h-5`, lg → `h-7`

Accessibility:
- Outer div: `role="progressbar"`, `aria-valuenow={value}`, `aria-valuemax={max ?? 100}`, `aria-valuemin={0}`, `aria-label={label ?? variant}`
- These ARIA attributes are required for screen readers to announce progress bar state

When `showValue` is true, render a positioned span inside the track showing `{value}/{max}` (or `{value}%` if no max). Use absolute positioning centered in the track with `text-xs font-jrpg text-jrpg-text` styling. Only show text on md/lg sizes (sm is too small for text).

Use `cn()` from `@/lib/utils` for class merging.

Create `client/src/components/ui/HealthBar.tsx` — a specialized health bar that dynamically changes fill color based on current HP percentage.

Props interface:
```typescript
interface HealthBarProps {
  value: number;        // Current HP
  max: number;          // Maximum HP
  label?: string;       // ARIA label (default: "Health")
  showValue?: boolean;  // Show "value/max HP" text overlay
  size?: 'sm' | 'md' | 'lg';
  className?: string;
  animated?: boolean;   // Enable pulse animation at low HP (default: true)
}
```

Implementation:
1. Calculate percentage: `const pct = Math.max(0, Math.min(100, (value / max) * 100))`
2. Dynamic color based on percentage thresholds:
   - `pct > 50` → `var(--jrpg-health-high)` (green)
   - `pct > 25` → `var(--jrpg-health-mid)` (yellow)
   - `pct <= 25` → `var(--jrpg-health-low)` (red)
3. Apply color via inline `style={{ backgroundColor: color }}` on the fill div (not Tailwind class, because the color is dynamically computed)
4. Fill width uses `transition: width 0.5s ease-out, background-color 0.3s ease` — both width AND color transition smoothly
5. When `animated` is true and `pct <= 25`, add a CSS `animate-pulse` class to the fill div for a low-HP warning effect. Respect `prefers-reduced-motion` by checking `window.matchMedia('(prefers-reduced-motion: reduce)').matches` — if true, skip the pulse animation.
6. Track styling matches StatBar: `bg-jrpg-panel` background, border from tokens, rounded, overflow-hidden

When `showValue` is true, show `{value}/{max} HP` centered in the track.

Accessibility:
- Same ARIA progressbar attributes as StatBar
- `aria-label` defaults to "Health" if not provided

IMPORTANT: HealthBar is NOT a wrapper around StatBar. It's a standalone component because its dynamic color logic (threshold-based) is fundamentally different from StatBar's static per-variant colors. Sharing code would create coupling without benefit.
