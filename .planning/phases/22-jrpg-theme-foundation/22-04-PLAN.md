Create `client/src/lib/hooks/useGameSounds.ts` — a semantic mapping layer between game events and the useAudio store.

This hook does NOT create new Audio objects. It maps semantic event names to existing useAudio store functions. This allows components to call `sounds.onButtonClick()` instead of knowing about `playButtonSelect()`, and provides a single place to swap sound mappings when new SFX are added later.

```typescript
import { useAudio } from '@/lib/stores/useAudio';

export function useGameSounds() {
  const audio = useAudio();

  return {
    // UI interactions
    onButtonClick:     audio.playButtonSelect,
    onConfirm:         audio.playSuccess,
    onError:           audio.playHit,        // Temporary: reuse hit sound for error

    // Game events
    onPhaseTransition: audio.playSuccess,    // Temporary: reuse success sound
    onPanelOpen:       audio.playButtonSelect, // Temporary: reuse button-select
    onPanelClose:      audio.playButtonSelect, // Temporary: reuse button-select
    onLevelUp:         audio.playLevelUp,
    onDamage:          audio.playHit,
    onExplosion:       audio.playExplosion,
  };
}
```

Also export a non-hook version for use outside React components (e.g., in event handlers that don't have hook access):

```typescript
export function getGameSounds() {
  const state = useAudio.getState();
  return {
    onButtonClick:     state.playButtonSelect,
    onConfirm:         state.playSuccess,
    onError:           state.playHit,
    onPhaseTransition: state.playSuccess,
    onPanelOpen:       state.playButtonSelect,
    onPanelClose:      state.playButtonSelect,
    onLevelUp:         state.playLevelUp,
    onDamage:          state.playHit,
    onExplosion:       state.playExplosion,
  };
}
```

Keep the existing `PhaseTransitionProps` interface but simplify it. The new component only needs:
```typescript
interface PhaseTransitionProps {
  fromPhase?: GamePhase;
  toPhase: GamePhase;
  isTransitioning?: boolean;   // Keep for API compat but AnimatePresence handles it via key
  onTransitionComplete?: () => void;
  children?: React.ReactNode;
}
```

New implementation:
```typescript
const phaseVariants = {
  hidden:  { opacity: 0, y: 16, scale: 0.97 },
  visible: { opacity: 1, y: 0,  scale: 1 },
  exit:    { opacity: 0, y: -16, scale: 0.97 },
};

export function PhaseTransition({
  fromPhase,
  toPhase,
  isTransitioning,
  onTransitionComplete,
  children
}: PhaseTransitionProps) {
  const shouldReduceMotion = useReducedMotion();
  const sounds = useGameSounds();
  const prevPhaseRef = useRef(toPhase);

  // Play phase transition sound when phase actually changes
  useEffect(() => {
    if (prevPhaseRef.current !== toPhase) {
      sounds.onPhaseTransition();
      prevPhaseRef.current = toPhase;
    }
  }, [toPhase, sounds]);

  const transition = shouldReduceMotion
    ? { duration: 0 }
    : { duration: 0.25, ease: 'easeInOut' as const };

  return (
    <AnimatePresence mode="wait" onExitComplete={onTransitionComplete}>
      <motion.div
        key={toPhase}
        variants={phaseVariants}
        initial="hidden"
        animate="visible"
        exit="exit"
        transition={transition}
        style={{ width: '100%', height: '100%' }}
      >
        {children}
      </motion.div>
    </AnimatePresence>
  );
}
```

CRITICAL: The `key={toPhase}` is what triggers AnimatePresence exit/enter animations. When `toPhase` changes, the old child exits and the new child enters. Do NOT use a static key.

**usePhaseTransition hook** — Simplify to remove setTimeout logic. The hook now only tracks phase changes for the caller (PhaseRenderer uses it):
```typescript
export function usePhaseTransition(currentPhase: GamePhase) {
  const [previousPhase, setPreviousPhase] = useState<GamePhase | undefined>();

  useEffect(() => {
    return () => {
      setPreviousPhase(currentPhase);
    };
  }, [currentPhase]);

  return {
    previousPhase,
  };
}
```

Remove the `TransitionState` interface and all `transitionState` / `getTransitionStyle` / overlay logic — AnimatePresence handles all of this.

**PhaseRenderer.tsx** — Update to remove `isTransitioning` prop passing since AnimatePresence handles transition state automatically via key changes. The PhaseTransition component no longer needs `isTransitioning` to be true to animate — it animates whenever `key` (toPhase) changes.

Keep the existing PhaseRenderer structure but simplify: remove `isTransitioning` from the `PhaseTransition` call if it's only passed through. The `isTransitioning` prop on PhaseRenderer can remain in the interface for backward compat but doesn't need to be passed to PhaseTransition.
