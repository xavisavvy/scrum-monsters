<objective>
Open the MAINT-03 testability seam: (1) extract the 9 module-scope `eventBus.on(...)` registrations in
`server/domains/index.ts` into a `wireDomains(ctx): { dispose() }` factory, with each listener stored
in a named `const` so `dispose()` can `eventBus.off(...)` it individually; the production call at the
module bottom is unchanged (it just discards the returned handle). (2) Add a server-side
`makeMockSocket` helper at `server/test/makeMockSocket.ts`, modeled on the client helper but extended
with `data`, `join`, and capture arrays. (3) Extract the `create_lobby`, `disconnect`/host-transfer,
and `reconnect_with_token` handler bodies into standalone `handle*(socket, data, deps)` functions in a
new `server/websocket.handlers.ts`, called from `setupWebSocket`, and unit-test all three via the mock
socket.

Purpose: Domain wiring and socket handlers are currently unreachable by unit tests (closure-bound
inside `setupWebSocket`, and listeners registered at module scope with no teardown). This seam makes
them testable and gives every later refactor a teardown-safe wiring factory. It also fixes the
pre-existing `MaxListenersExceededWarning` by establishing the fresh-bus-per-test pattern.

Output: `wireDomains` factory, `makeMockSocket`, extracted handlers, three handler tests, a dispose test.

INVARIANT (non-negotiable): byte-identical production behavior. The module-bottom `wireDomains(...)`
call registers the same 9 listeners with the same handler bodies; `setupWebSocket` still produces the
same socket behavior (handlers extracted, not changed). Full suite stays green.
</objective>
