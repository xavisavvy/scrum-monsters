## Verification

After this plan: three previously-broken features work. Phase 45 success criteria 5, 6, 7 satisfied.

## Risk

Medium-high. Adding new events and new UI is real product work, not type-system cleanup. Each of the three features has real failure modes:

- **Revival progress** — tick interval might fire too frequently (network spam) or too slowly (jittery bar). Reuse the existing CombatManager interval, don't add a new one.
- **YouTube sync** — IFrame API has strict load-order requirements; calling loadVideoById on a not-yet-ready player crashes. Guard with `useAudio.getState().youtubePlayer?` and accept that early peers may miss the first sync (acceptable per user decision).
- **Heal popup** — must not break the existing damage popup. The shared floating-popups state slice is the integration point; add a `type: 'damage' | 'heal'` discriminator and let the renderer handle styling.

Smoke testing in Task 7 is the safety net. If any of the three breaks something else, that feature can be rolled back independently (each is its own task series).
