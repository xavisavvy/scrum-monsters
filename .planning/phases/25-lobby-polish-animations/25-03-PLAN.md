  <action>
Add a subtle Framer Motion Y-axis bobbing to character sprites in the lobby to complement the sprite frame cycling from Task 1. This creates a layered idle effect: sprite frames shift weight + entire character gently bobs.

**1. Add motion import at the top of Lobby.tsx:**

After the existing React imports, add:
```typescript
import { motion } from 'framer-motion';
```

**2. Find where SpriteRenderer is rendered for player characters in the lobby.**

There will be sections where `<SpriteRenderer>` is used inside the lobby player rendering area. Look for the current player's sprite and other players' sprites. Typical pattern:

```tsx
<SpriteRenderer
  avatarClass={player.avatar || player.avatarClass}
  animation="idle"
  ...
/>
```

**3. Wrap each SpriteRenderer with a motion.div bobbing animation.**

For each `<SpriteRenderer>` in the lobby (both current player and other players), wrap it:

```tsx
<motion.div
  animate={{ y: [0, -3, 0] }}
  transition={{
    duration: 2.5,
    repeat: Infinity,
    ease: 'easeInOut',
    repeatType: 'loop',
  }}
>
  <SpriteRenderer ... />
</motion.div>
```

**Key considerations:**

- Apply `animate={{ y: [0, -3, 0] }}` — 3px bobbing range is subtle enough to feel like breathing, not bouncing
- `duration: 2.5` seconds per full cycle — slow enough to feel calm/idle
- `repeat: Infinity` with `repeatType: 'loop'` for seamless looping
- `ease: 'easeInOut'` for smooth acceleration at top and bottom of bob

**4. Only apply bobbing when the character is NOT moving.**

If the character is currently walking (isMoving state), do NOT apply bobbing — the walk animation handles that. Check the `isMoving` state for each player:

For the current player, check if any movement keys are pressed (the `keys` state Set). If `keys.size === 0`, the player is idle and should bob.

For other players, check the `playerPositions[player.id]?.isMoving` field. If `false` or undefined, apply bobbing.

```tsx
{!isPlayerMoving ? (
  <motion.div
    animate={{ y: [0, -3, 0] }}
    transition={{ duration: 2.5, repeat: Infinity, ease: 'easeInOut', repeatType: 'loop' }}
  >
    <SpriteRenderer ... />
  </motion.div>
) : (
  <SpriteRenderer ... />
)}
```

**5. Do NOT apply bobbing to non-lobby phases.** The lobby component only renders in lobby phase, so this is inherently scoped. But if SpriteRenderer is also used elsewhere in this file, only wrap the lobby-specific renderings.

**Performance note:** Framer Motion Y-axis transforms are GPU-accelerated (composited layer). Adding a motion.div wrapper per player (max 8) is negligible overhead. The existing `requestAnimationFrame` loop in `useSpriteAnimation` runs regardless, so there is no additional animation scheduling cost.
