# Milestone v1.2: SDLC Best Practices

**Status:** SHIPPED 2026-02-03
**Phases:** 7-14
**Total Plans:** 21

## Overview

v1.2 matures the CI/CD infrastructure with engineering best practices: PR quality gates, security scanning, test coverage enforcement, visual regression testing, database migrations, API contracts, load testing, and deployment safety. The approach is incremental, starting with low-risk CI improvements that provide immediate value, then progressing to infrastructure-heavy features like migrations and rollback automation.

## Phases

### Phase 7: CI Foundations

**Goal**: PRs have quality gates enforced before merge
**Depends on**: Nothing (v1.1 CI infrastructure exists)
**Plans**: 2 plans

Plans:
- [x] 07-01: PR templates, CODEOWNERS, and Vitest coverage thresholds
- [x] 07-02: CI coverage reporting and branch protection configuration

**Details:**
- PR templates with summary, test plan, and checklist sections
- Branch protection requiring 1 reviewer approval
- CI must pass before merge (lint, test, build, security)
- Coverage thresholds at 12% baseline with PR diff reporting
- Dynamic coverage badge via gist

### Phase 8: Security Hardening

**Goal**: Security issues caught before code reaches main branch
**Depends on**: Phase 7 (branch protection must exist)
**Plans**: 2 plans

Plans:
- [x] 08-01: CodeQL merge blocking via rulesets and gitleaks secret detection
- [x] 08-02: Dependency vulnerability scanning (audit-ci) and license compliance (license-checker)

**Details:**
- CodeQL SAST blocks PRs with high/critical findings
- Pre-commit and CI gitleaks detect secrets before push
- audit-ci blocks high/critical npm vulnerabilities
- license-checker enforces permissive license compliance

### Phase 9: Database Migrations

**Goal**: Schema changes deploy safely through versioned migrations
**Depends on**: Phase 8 (security scanning validates migration files)
**Plans**: 3 plans

Plans:
- [x] 09-01: Local migration workflow with npm scripts and initial migration
- [x] 09-02: CI migration validation with PostgreSQL service container
- [x] 09-03: ArgoCD PreSync hook for deployment migration execution

**Details:**
- Drizzle versioned migrations replace db:push
- CI validates migrations are generated for schema changes
- ArgoCD PreSync Job runs migrations before app deployment
- Failed migrations block deployment

### Phase 10: Visual Regression

**Goal**: UI changes detected and reviewed before merge
**Depends on**: Phase 7 (CI foundations for test infrastructure)
**Plans**: 3 plans

Plans:
- [x] 10-01: Visual test infrastructure (Playwright config, helpers, CSS)
- [x] 10-02: Visual regression test specs for game flow
- [x] 10-03: CI workflow and PR labeling for visual changes

**Details:**
- Playwright captures screenshots of key UI states
- CI compares screenshots against baseline
- Visual failures block PR merge
- Auto-label 'visual-changes' makes baseline updates visible

### Phase 11: Accessibility Testing

**Goal**: Accessibility violations caught in CI before merge
**Depends on**: Phase 7 (CI foundations for E2E tests)
**Plans**: 3 plans

Plans:
- [x] 11-01: A11y test infrastructure (fixture, helpers, npm script)

- [x] 11-03: CI workflow with PR comments and artifact upload

**Details:**
- axe-core accessibility scans on critical paths

### Phase 12: API Contract Testing

**Goal**: API changes validated against documented spec
**Depends on**: Phase 7 (CI foundations for validation)
**Plans**: 3 plans

Plans:

### Phase 13: Load Testing

**Goal**: Performance baselines established and tracked
**Depends on**: Phase 7 (CI foundations for test jobs)
**Plans**: 3 plans

Plans:
- [x] 13-01: HTTP load test infrastructure (smoke + average load tests)

### Phase 14: Rollback Automation

**Goal**: Failed deployments can be recovered quickly and safely
**Depends on**: Phase 9 (migrations must be stable for rollback to be meaningful)
**Plans**: 2 plans

Plans:

**Details:**
- GitHub workflow triggers ArgoCD rollback
- Production requires manual approval
- Auto-rollback for dev/staging on health failure
- JSONL audit trail committed to repository

## Milestone Summary

**Key Decisions:**
- Coverage threshold at 12% baseline (pragmatic start, raise incrementally)
- CodeQL blocks high/critical only (reduce noise from low-risk issues)
- License check on production dependencies only (dev tools excluded)
- ArgoCD PreSync hook for migrations (run once per sync, not per pod)
- Load tests never block PRs (informational only)
- Auto-rollback disabled for production (manual intervention required)

**Issues Resolved:**
- Branch protection enforcing CI gates and reviewer approval
- Security scanning catching vulnerabilities before merge
- Database migrations validated and applied automatically
- Visual regression baselines generated with platform-agnostic paths
- API contracts validated with Schemathesis

**Technical Debt Incurred:**
- TEST-01 pragmatic deviation: 12% coverage baseline instead of 70% target
- 2 visual test specs skipped (reveal, victory) until game state setup available
- Orphaned type exports (api-types.generated.ts, socket-schemas.ts) not imported in production
