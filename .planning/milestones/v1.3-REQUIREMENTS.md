# Requirements: ScrumQuest v1.3 Game Progression

**Defined:** 2026-02-03
**Core Value:** Focused estimation that doesn't bore people. Voting should be distraction-free, but waiting for others should be fun.

## v1.3 Requirements

All 33 requirements shipped and validated.

### XP/Progression

- [x] **XP-01**: Player earns XP on vote submission
- [x] **XP-02**: Player earns XP on boss damage dealt
- [x] **XP-03**: Player earns bonus XP for consensus match (voting accuracy)
- [x] **XP-04**: Player earns XP for reviving teammates
- [x] **XP-05**: Player XP persists across sessions (account-level)
- [x] **XP-06**: Player level calculated from total XP using progression curve
- [x] **XP-07**: Player sees XP bar with current progress to next level
- [x] **XP-08**: Player sees level-up notification with celebration effect

### Class Mastery

- [x] **MSTR-01**: Player earns class-specific XP when playing a class
- [x] **MSTR-02**: Class mastery has tier progression (Novice -> Expert -> Master)
- [x] **MSTR-03**: Class mastery tier grants stat bonuses (HP, damage, cooldown reduction)
- [x] **MSTR-04**: Class mastery tier unlocks class-specific abilities

### Boss AI

- [x] **BOSS-01**: Each boss type has unique attack pool (5 bosses, distinct patterns)
- [x] **BOSS-02**: Boss enters different phases based on HP thresholds
- [x] **BOSS-03**: Boss attacks have telegraphing (visual warning before damage)
- [x] **BOSS-04**: Boss difficulty scales with team average level
- [x] **BOSS-05**: Boss enters enrage mode at low HP (faster attacks, more damage)
- [x] **BOSS-06**: Boss targets players based on threat (damage dealt, healing done)

### Class Abilities

- [x] **ABIL-01**: Each avatar class has 1-2 unique abilities
- [x] **ABIL-02**: Abilities have cooldown timers (server-authoritative)
- [x] **ABIL-03**: Player sees ability buttons with cooldown indicators
- [x] **ABIL-04**: Ability effects vary by class role (tank: taunt/shield, healer: heal/buff, DPS: damage/debuff)

### Team Combos

- [x] **CMBO-01**: Specific class combinations trigger combo attacks
- [x] **CMBO-02**: Consensus-powered ultimate activates when entire team has voted
- [x] **CMBO-03**: Combo attacks deal bonus damage and have visual effects

### Combat Items

- [x] **ITEM-01**: Items are session-scoped consumables (no persistence between games)
- [x] **ITEM-02**: Items have effects: heal, damage boost, shield
- [x] **ITEM-03**: Player receives items on ticket completion
- [x] **ITEM-04**: Player can use items during combat phase

### Lifetime Stats

- [x] **STAT-01**: Track lifetime estimation stats (total votes, consensus rate, voting speed)
- [x] **STAT-02**: Track lifetime combat stats (damage dealt, bosses defeated, revives, deaths)
- [x] **STAT-03**: Display lifetime stats on player profile page
- [x] **STAT-04**: Display session stats in game over summary

## Future Requirements

Deferred to v1.4 or later. Tracked but not in current roadmap.

### Prestige/Endgame

- **PRSTG-01**: Player can prestige after max level (reset level, keep cosmetic rewards)
- **PRSTG-02**: Prestige grants exclusive cosmetic unlocks

### Leaderboards

- **LEAD-01**: Weekly leaderboards for XP gained
- **LEAD-02**: Sprint-scoped leaderboards for teams

### Advanced Boss AI

- **ADVBOSS-01**: Boss learns player patterns across sessions (adaptive AI)
- **ADVBOSS-02**: Boss remembers players between sessions

## Out of Scope

Explicitly excluded from v1.3. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Persistent inventory | Items session-scoped for v1.3; persistence adds complexity |
| Multi-class combo chains | Requires extensive balancing; 2-class combos sufficient for v1.3 |
| XP penalties for "wrong" votes | Undermines scrum collaboration theme |
| Pay-to-win progression | Violates core value of focused estimation |
| UI redesign | Deferred to v1.4 UI Polish milestone |
| Mobile responsiveness | Deferred to v1.4 UI Polish milestone |
