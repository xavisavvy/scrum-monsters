KEY FINDINGS:

Stack:
- Docker + Docker Compose (single-instance orchestration)
- PostgreSQL 16-alpine (200M limit) + Redis 7-alpine (50M limit)
- Prometheus (100M, 7-day retention) + Loki (75M) + Grafana (80M)
- Nginx reverse proxy (host-level, 30M)
- Node.js 20-alpine app (128M limit with 64M V8 heap)
- All existing code preserved (no breaking changes)

Architecture:
- Single Lightsail instance (1GB RAM, 1 vCPU, $5/mo)
- 10 Docker containers orchestrated by docker-compose.yml
- Health checks gate service startup (prevents cascading failures)
- Graceful shutdown reuses existing 30s SIGTERM handler
- PostgreSQL named volume survives restarts
- Logging to stdout + Promtail → Loki (no file-based logs)
- Reverse proxy (Nginx) handles TLS + routing

Data Flow:
1. Developer: git push main
2. GitHub Actions: lint, test, build, docker build, push to ECR
3. Lightsail: docker-compose pull && docker-compose up -d
4. Prometheus scrapes app /metrics every 15s
5. Loki receives logs from Promtail, searchable in Grafana
6. Daily 2 AM cron: pg_dump → gzipped backup (7-day retention)

Pitfalls Identified:
- CRITICAL: 1GB RAM constraint requires strict memory limits (683 MB container requests max)
- Any container exceeding limit = OOM kill (cascading failures if not isolated)
- No health checks = zombie containers (appear running but broken)
- File-based logs in containers = lost on restart (use stdout)
- Unbounded memory usage = system pressure/OOM (use limits)
- Manual deployments = human error at scale (automate)

- PRESERVED: All existing code unchanged
